# 도로 CLI 오케스트레이터

프로젝트 대화의 GPT Work가 본작업과 최종 판단을 맡고, 사용자가 요청할 때 Claude Code와 검토·반론·보완을 주고받는다. 기존 Codex CLI 중심 실행 모드도 유지한다. AGY의 기본값은 `enabled = false`이며 꺼진 참가자는 버전·인증·모델 목록 확인도 실행하지 않는다.

## 프로젝트에서 협업하기

```bash
python3 tools/install_work_skill.py
```

설치기는 `~/.codex/skills/doro-orchestration/`에 개인 스킬을 만들고 `~/.codex/skill-docs/doro-orchestration.json`에 이 실행기 위치를 등록한다. 다른 설치본이나 사용자 수정이 있으면 덮어쓰지 않는다. 설치 후 프로젝트의 **Work 대화에서** “도로, 오케스트레이션 시작해줘” 또는 “Claude와 같이 검토해줘”라고 요청한다. 명시적으로 스킬을 고를 때는 `$doro-orchestration`을 사용한다. 새 스킬이 보이지 않으면 앱의 스킬 목록을 새로고침하거나 새 대화에서 확인한다.

기본 설치는 명시적인 협업 요청 때만 시작한다. 창을 협업 스위치로 사용하려면 `./doro window policy --require-running`으로 설정한다. 이후 현재 요청한 프로젝트 작업은 창이 실행 중일 때 준비된 참가자와 협업하고, 창 열기·조회·일반 질문만으로 새 프로젝트나 모델 호출을 만들지는 않는다. 요청을 받으면 현재 Work가 초안을 만들고 Claude의 실제 검토를 읽어 보완한다. 필요할 때 검토를 더 요청하고 현재 Work가 최종 결과를 기록·통합한다. 검토·상호작용 횟수의 고정 상한은 없다. 별도 Codex CLI를 메인으로 중복 실행하지 않는다. 작업 파일이나 전체 대화를 자동 수집하지 않는다.

스킬은 `work start`(로컬 초안 저장, 호출 없음), `work review --send`(Claude 호출), `work reply`(Work 보완), `work finish`(Work 최종 판단), `work status`(호출 없는 조회)를 사용한다. 검토 한 번으로 충분하면 일찍 마무리할 수 있다. 두 실행 모드는 외부 호출 코드와 SQLite 장부를 공유한다. 새 Work 협업에는 누적 횟수·토큰·시간·추정 비용 상한을 두지 않으며, 독립 CLI와 `work start --bounded`는 기존 제한을 쓴다. Work 모드의 보고 토큰·비용은 외부 Claude 호출만 포함하며 현재 Work 대화 자체의 사용량은 포함하지 않는다.

### 진행 중 관찰과 승인

Work 협업은 **시작 범위·중요 분기·실제 파일 반영 전**에 사용자 결정을 기다린다. `work start`는 `awaiting_approval`로 저장하며 Claude 인증 확인이나 모델 호출을 시작하지 않는다. 현재 Work가 전달할 구체적인 입력과 범위를 대화에 제시하고 사용자 입력 도구로 질문한다. 사용자의 실제 답이 오면 현재 체크포인트 ID에 결정을 기록한다. 이미 받은 구체적인 동일 범위의 승인은 재사용한다. 승인된 범위 안의 모든 검토 턴마다 질문을 반복하지 않는다.

```bash
./doro work decide <UUID> --checkpoint <현재-체크포인트-ID> --decision approve
./doro work review <UUID> --send
./doro work checkpoint <UUID> --kind branch --summary work/branch.txt
./doro work checkpoint <UUID> --kind apply --summary work/proposed-change.txt
```

`decide`는 신뢰되는 현재 Work 또는 사용자의 로컬 명령이 내리는 결정을 기록한다. 사람 신원을 독립적으로 인증하는 보안 장치는 아니므로 Work가 실제 사용자 답을 확인해야 한다. Claude 출력·기본 선택·시간 경과는 승인이 아니다. 오래된 ID·중복 응답은 거부하고, 대기 중에는 다음 모델 호출·Work 보완·완료를 거부한다. `--decision reject`는 `awaiting_direction`에서 멈추고, 수정된 같은 종류의 체크포인트를 다시 승인하기 전에는 진행하지 않는다. 기존 v1/v2 세션은 조회할 수 있지만 과거 기록을 새 승인으로 간주하지 않는다.

중요 분기의 의미를 판단하고 필요한 체크포인트를 여는 일은 현재 Work의 책임이다. `work finish`는 최종 발언만 기록한다. 실행기는 프로젝트 파일을 수정하지 않으며, 실제 파일 반영 승인과 반영·검증은 현재 Work가 책임진다. 따라서 실행기가 현재 Work의 모든 파일 접근을 운영체제 수준에서 차단한다고 보장하지 않는다.

진행은 공식 펫 옆에서 쓰는 macOS 대화창에서 볼 수 있다. GPT와 Claude의 실제 발언은 왼쪽, 사용자 입력은 오른쪽이다. 중립적인 흰색·회색 말풍선을 쓰고 긴 발언은 펼쳐 본다. 새 창은 기본 390×590 포인트이며 대화 부분을 스크롤한다. Claude/AGY 점은 협업 참여 켜짐·꺼짐을 뜻하며 인증·구독 잔여량 표시가 아니다. 공식 펫과 이미지는 그대로 둔다.

모델 응답을 기다리지 않고 열려면 **도로협업.app**을 누르거나 작업창 실행 중 **⌃⌥Enter(Control+Option+Enter)**를 누른다. 메뉴 막대 말풍선을 누르면 그 아래에 대화 목록이 열리며, 다시 누르면 창만 숨긴다. 우클릭·Control 클릭으로 대화·숨기기·종료 메뉴를 연다. 앱을 완전히 종료하면 전역 단축키도 해제되므로 바로가기 앱으로 다시 실행한다. 단축키 충돌이 감지되면 창에 안내하고 다른 앱의 단축키를 빼앗지 않는다. 시스템 예약 단축키의 모든 충돌을 감지하지는 못한다.

로컬 바로가기 설치는 다음 명령을 쓴다. 네이티브 창을 미리 빌드하고 `~/Applications/도로협업.app`을 만든다. Dock·Spotlight에서 사용할 수 있으며 Work·모델 호출·계정 변경 없이 기존 창을 연다. 로그인 시 자동 실행 설정은 바꾸지 않는다.

실행 잠금은 Mac 사용자 전체에서 공유한다. 같은 설치본을 반복 실행하면 기존 창을 재사용하며 요청은 순서대로 처리한다. 다른 작업 폴더의 복사본은 두 번째 앱을 띄우거나 기존 작업의 연결을 바꾸지 않고 오류로 알린다. 종료·충돌 뒤에는 OS가 잠금을 해제한다. 시험본과 설치본을 동시에 실행하지 않는다.

```bash
python3 -m tools.install_window_shortcut
```

공식 펫 입력창에서 **“오케스트레이션 켜줘”**, **“도로 협업창 켜줘”**라고 하면 설치된 스킬은 검색·새 Work 생성보다 로컬 창 열기를 먼저 실행한다. 자동 선택이 안 되면 **`$doro-orchestration 협업창 켜줘`**로 요청한다. 공식 닷츠의 자연어 입력을 모델보다 먼저 로컬 명령으로 처리하는 연결은 구현되지 않았다. 자연어 요청은 Chat/Work 응답 지연이 남을 수 있으므로 즉시 열기는 바로가기·단축키를 쓴다.

```bash
./doro window open
./doro window open --session <등록된-UUID>
./doro window minimize
./doro window hide
./doro chat <UUID> --display panel
./doro chat <UUID> --text
./doro inputs pending <UUID> --owner-thread <소유-Work-ID>
./doro inputs wait <UUID> --owner-thread <소유-Work-ID> --timeout 55
./doro inputs ack <입력-ID> --owner-thread <소유-Work-ID> --response work/reply.txt
```

메뉴 막대 아이콘을 다시 누르거나 다른 앱·바탕화면을 누르면 창을 숨기고 메뉴 아이콘을 남긴다. 메뉴 막대 아이콘을 우클릭해 **종료**를 누르면 UI 앱과 아이콘을 닫으며 원래 GPT Work·실행 기록은 유지한다. Spotlight(Command+Space)에서 **도로협업**을 검색해 다시 연다. 목록 행 전체를 누르면 대화가 열리고 상단 **대화** 버튼으로 목록에 돌아간다. 옆 화살표에서는 열어 둔 대화를 고른다. 입력 초안과 읽은 위치는 작업별로 저장해 재실행 뒤에도 복원한다. 목록 행의 `×`는 그 항목만 닫는다. 제목·가장자리·본문에서 끌어 창을 옮기고 목록 행·입력칸·스크롤바는 원래 조작을 유지한다. 말풍선은 우클릭으로 복사한다. 다른 작업의 메시지 전달 중에도 종료 메뉴는 잠시 비활성화된다.

**＋**에서 새 작업 내용을 쓰고 **시작** 또는 Enter를 누르면, 현재 연결된 GPT가 공식 앱 기능으로 별도의 새 GPT 대화를 만들고 협업창에 연결한다. GPT 대화 화면을 직접 열지 않는다. 현재 GPT가 바쁘면 생성 요청이 대기할 수 있다. 새 작업 초안과 기존 답장 초안은 따로 보존하며, 생성 결과를 확인하지 못한 요청은 자동 재시도하지 않는다. 새 대화 연결 자체는 Claude·AGY 전달이나 파일 반영 승인이 아니다. 공식 새 대화 생성 도구가 없는 환경에서는 실제 실패를 표시한다.

**Enter**는 보내기, **Shift+Enter**는 줄바꿈이다. 별도 보내기 버튼은 두지 않는다. 작업명과 전송 상태는 한 줄 상단바의 남는 영역에서 천천히 왕복 이동한다. 포인터를 올리거나 동작 줄이기가 켜져 있으면 멈추며 전체 문장은 도움말과 접근성 라벨로 읽을 수 있다. 입력 오류는 입력칸 가까이에 표시한다. 한글 조합 중 Enter는 글자 확정을 먼저 처리하며 바로 보내지 않는다. 입력 한도는 실행기가 제공하며 현재 2,000자다. 한글·이모지는 Python과 같은 유니코드 코드포인트로 계산한다. 전송 한도 초과나 저장 실패 때에는 내용을 보존하고 보내지 않는다. 초안·펼친 발언·읽은 위치·확인되지 않은 전송 ID는 로컬 `.doro/native/context-state.json`에 600 권한으로 저장한다. 토큰·계정 정보는 넣지 않으며 Claude에 전송하지 않는다. 불확실한 입력은 재실행 뒤에도 같은 ID를 유지하고 자동으로 재전송하지 않는다.

저장 파일을 읽지 못하면 오류를 표시하고 원본을 덮어쓰지 않는다. **원본 보관 후 복구**는 해당 파일을 같은 폴더의 `context-state.backup-<UUID>.json`으로 보관한 뒤 현재 입력을 저장한다. 자동 재전송은 없다. 저장할 수 없는 새 초안이나 확인되지 않은 입력이 있으면 종료를 멈추고 오류를 표시한다. 새로 작성한 내용이 없으면 기존 파일을 보존한 채 종료할 수 있다.

다른 대화로 옮길 때는 현재 초안과 필요한 목록 복원을 먼저 저장한다. 실패하면 선택·열림 상태·입력·읽던 위치를 유지한다. 같은 대화를 다시 여는 데에는 불필요한 저장을 요구하지 않는다. 목록 이력 저장 오류는 별도로 표시하며, 성공적으로 읽은 본문과 현재 질문은 계속 갱신한다. 이력이 실제로 저장되기 전에는 저장 완료로 취급하지 않는다.

위쪽 화살표는 대화를 dock 하나로 접는다. dock의 아래쪽 화살표는 펼치고 위쪽 화살표는 메뉴 막대로 숨긴다. dock·목록은 내용 크기로 고정하고 전체 대화만 크기를 조절한다. 다른 앱이나 바탕화면을 누르면 펼친 대화가 dock으로 접히고 초안·읽던 위치는 보존한다. 설정·승인창의 키보드 포커스 이동은 이 동작을 일으키지 않는다. 목록 높이는 첫 표시 전에 계산한다. **지난 대화**는 따로 펼칠 수 있다. 마우스로 행을 왼쪽으로 짧게 밀면 동작을 드러내며, 충분히 밀면 열린 항목은 닫고 지난 항목은 목록에서 지운다. 세로 이동과 작은 클릭 흔들림은 밀기로 처리하지 않는다. 드러난 행의 본문을 누르거나 Escape를 누르면 밀기를 취소한다. 트랙패드에는 macOS 목록의 기본 스와이프 동작을 사용한다. `×`와 휴지통 버튼도 유지한다.

지난 대화는 휴지통으로 하나씩 지우거나 `⋯`에서 선택·전체 지우기를 쓴다. 목록 표시만 지우고 원래 GPT 대화·실행 기록은 보존한다. 진행·승인·답변 대기 항목은 지우지 않는다. **삭제 취소**는 마지막에 지운 묶음을 복원한다. 삭제 상태와 복원 정보는 재실행 후에도 유지하며 새 승인이 생기면 해당 작업을 다시 표시한다. 로컬 `.doro/native/stack-history.json`에는 항목 ID만 저장한다. 목록 창은 펼친 내용 높이에 맞춰 줄고 늘며, 길어지면 최대 높이에서 스크롤된다. 대화창 크기는 따로 보존한다.

창을 열 때 메뉴 아이콘 아래에 놓고 화면의 남는 영역에 맞춘다. 표시 중 메뉴 아이콘이 움직이면 창도 같은 방향으로 따라간다. 직접 드래그한 간격은 유지하며 숨겼다가 다시 열거나 메뉴가 다른 화면으로 옮겨지면 아이콘 아래에 다시 맞춘다. Dock 크기 변경만으로 드래그 위치를 초기화하지 않는다. 폴링만으로 창을 다시 배치하지 않는다. 공식 펫 좌표를 읽거나 펫 위치에 따라 자동 이동하지 않는다.

접기·밀기 정착·목록 높이·메뉴 위치 이동은 짧은 0.22초 모션을 공유한다. 드래그 중 행은 포인터를 직접 따라가며 추가 애니메이션을 겹치지 않는다. macOS의 **동작 줄이기**를 켜면 해당 전환은 즉시 반영한다.

숨긴 동안에는 3초 간격으로 작업 목록 메타데이터만 갱신해 메뉴 아이콘의 승인 수를 유지한다. 대화 본문을 가져오거나 창·승인창을 자동으로 열지 않으며 모델 호출도 없다.

공식 펫과 원본 이미지는 그대로 둔다. 기본 대화창은 `--display panel`이며 추가 캐릭터나 자동 교대를 쓰지 않는다.

대화 입력과 별도 승인/보류 버튼은 정확한 세션·소유 Work·현재 질문에 묶인다. UI 토큰 검증 뒤 입력과 전달 대기를 함께 저장하고, 공식 [`codex queue`](https://learn.chatgpt.com/docs/developer-commands#codex-queue)로 기존 Work UUID에 ID 표식만 넣는다. Work가 이를 받아 실제 입력을 확인한 뒤 답하고, 현재 질문에만 결정한다. 입력 원문과 토큰은 프로세스 인자나 Claude에 자동 전달하지 않는다. 앱 자체의 도구 권한은 이 버튼으로 대신 승인하지 않는다.

같은 입력은 한 번만 송신한다. 큐 접수는 실제 Work 수신·파일 반영과 구분한다. 확정 실패에는 ‘다시 보내기’를 제공하고 불확실한 전송은 자동 반복하지 않는다. Codex 앱이 실행 중이어야 하며 실제 수신·답변이 확인돼야 재개 성공이다. 별도 Codex 메인 작업을 실행하지 않는다.


대화 버튼 옆 Claude·AGY 설정의 탭에서 작업별 모델과 생각 수준을 선택한다. AGY 사용 여부는 별도로 저장하며 준비를 확인하지 못하면 점은 회색이고 이유를 표시한다. 다음 검토부터 적용하며 저장만으로 호출하지 않는다. Claude의 실제 응답 모델은 반환 메타데이터로 표시한다. AGY는 CLI 초기화에서 확인한 핀값을 최근 CLI 모델로 표시하며 서버 반환 모델이라고 단정하지 않는다. 로컬 기본값 예:

```bash
./doro model --model claude-opus-5-5 --effort medium
```

Claude는 세션 저장을 끄고 도구를 제한해 실행한다. Claude 대화 목록에 별도 세션을 저장하지 않으며 로컬 실행기가 실제 입력·응답을 이어 간다. 원래 GPT 대화에도 전달 범위, 실제 검토 요지, GPT 판단과 결과를 남긴다. 실제 구독 소비·응답 모델은 호출 결과에 근거해 보고한다. 기존 `pet-swap`·`--display integrated` 명령은 호환성을 위해 보존하며 별도 명시 요청 전에는 사용하지 않는다.

macOS SDK가 현재 Swift 도구와 맞지 않아 빌드가 실패할 경우 호환되는 SDK의 절대 경로를 로컬 `.doro/native/sdk-path` 한 줄에 지정할 수 있다. 지정한 경로가 없으면 명확히 실패하며 임의 대체하지 않는다. 이 파일은 개인 설정이며 Git에 넣지 않는다.

## 실행

Python 3.11 이상, PATH에 설치된 `codex`와 `claude`, 기존 구독 계정 로그인이 필요하다. 실행기 자체에는 추가 Python 패키지가 필요 없다. 프로젝트 폴더에서 실행한다.

```bash
./doro doctor
./doro plan --task examples/smoke.json
./doro run --task examples/smoke.json --send
```

`run`도 `--send`가 없으면 전달할 입력과 계획만 보여준다. 새 작업은 예시 JSON을 복사해 `message`와 `context`에 **외부 모델에 전달해도 되는 내용만 직접** 작성한다. `classification: "public"`과 수신 모델 목록을 명시해야 한다. 저장소, 문서, 대화 내역, 파일 첨부를 자동 수집하는 기능은 없다. 비공개 입력은 거부된다. 인식할 수 있는 키·토큰·이메일·개인 절대 경로도 검사한다. 이 검사는 모든 형태의 개인정보를 판별하는 분류기가 아니므로 공개 여부는 작성자가 확인한다.

```bash
./doro show <출력된-세션-UUID>
./doro resume <출력된-세션-UUID> --send
```

실패한 세션은 자동 재시도하지 않는다. 명시적 `resume`은 완료된 턴을 건너뛰고 실패한 단계부터 이어 간다. 이전 호출·예약 비용·사용량은 유지한다. 설정이나 역할 지침이 바뀌면 기존 세션 재개를 거부한다. 실행 중에는 Ctrl+C로 중단한다. 진행 중인 프로세스 그룹을 종료하고 세션을 `interrupted`로 기록한다. 같은 세션의 동시 실행도 거부한다.

## 시작 범위의 구성 불일치 복구

Work의 시작 질문이 아직 미해결인데 설정·역할 지침이 변경돼 승인을 기록하지 못하면, `work status <UUID>`에서 저장/현재 지문과 `session_sha256`을 확인한다. 사용자가 명시적으로 요청한 복구는 다음 명령으로 수행한다. 기존 소유 Work에서만 실행하고, 공개 입력 두 파일의 바이트 해시와 현재 상태·구성을 지정한다.

```text
./doro work recover <UUID> --owner-thread <Work UUID> --checkpoint <시작 질문 UUID>
  --expected-state <session_sha256> --expected-config <current_fingerprint>
  --task <공개 JSON> --task-sha256 <SHA-256>
  --draft <공개 초안> --draft-sha256 <SHA-256> --reason <복구 이유 UTF-8 파일>
```

위 명령은 한 줄로 실행한다. 복구는 원래 task·초안과 구성 변경 이유를 보존하고 최신 공개 초안을 추가한다. 기존 질문·승인·호출·비용은 초기화하지 않으며 모델도 호출하지 않는다. 실제 사람의 기존 승인은 별도 `work decide`로 반영한다. 이후 외부 입력은 보존된 옛 초안 대신 복구 후 공개 초안부터 사용한다. 참가자 확대·검토 회수 변경·완료/실행 중/거절 상태는 이 명령으로 열지 않는다. 상태·구성·입력 파일이 관측 이후 달라지면 저장하지 않으며 구성 검사를 자동 해제하지 않는다.

## 역할과 전달 흐름

기본 흐름은 GPT 초안 → Claude 아이디어·검토 → GPT 반론·보완 → Claude 재검토 → GPT 최종 판단이다. 각 참가자는 이전 발언 전체를 명시적 텍스트 기록으로 받는다. Claude는 오류 지적 외에 새 접근법·대안·설계·사용 흐름 개선도 제안한다. Claude가 낸 제안과 반론은 GPT가 검토해 채택·기각 이유를 설명한다. `@codex` 같은 문자열은 발언의 일부이며 임의 호출이나 권한 확대를 일으키지 않는다. 모델 출력의 명령·코드를 자동 실행하거나 프로젝트에 자동 적용하지 않는다. GPT는 본작업의 코드·패치·해답을 만들며 결과 적용은 메인 작업 세션이 검토한 뒤 수행한다.

AGY / Argon이 켜져 있고 해당 공개 범위에 허용된 협업에서는 기존 `ideas` 단계로 새 아이디어·대안·설계나 사용 흐름 개선을 제안한다. 주요 제안에는 기대 효과, 장단점·구현 부담, 가정과 작은 확인 방법을 포함한다. GPT는 목적·근거·효과·복잡도·위험을 보고 유용한 안만 채택하거나 수정하고, 보류·기각 이유도 짧게 남긴다. 모두 기각할 수도 있다. 제안·채택·실제 반영·검증 결과를 같은 대화에 구분해 기록하며 필요할 때 Claude가 구현 가능성을 검토한다. 아이디어 요청 자체는 자동 파일 반영이나 입력 범위 확대가 아니다.

Claude와 AGY 모두 아이디어 개수에 고정 상한을 두지 않는다. 서로 다른 관점과 과감한 후보를 간결하게 폭넓게 받은 뒤 GPT가 좋은 안을 골라 다듬는다. 중복을 합치고 가설과 근거를 구분한다. 이는 자동 추가 호출이나 회당 입력·응답 제한 해제를 뜻하지 않는다.

`roles/codex.md`, `roles/claude.md`, `roles/agy.md`가 역할의 단일 출처다. CLI 자체의 대화를 재개하지 않고 매번 새로운 제한된 프로세스를 실행한다. 실행기가 SQLite 세션 기록과 턴 순서를 책임지므로 다른 프로젝트의 최근 대화가 섞이지 않는다. 실제 CLI의 응답 세션 ID도 각 턴에 기록한다.

## 제한과 실패 처리

독립 CLI 모드와 `work start --bounded`에서 사용하는 `orchestrator.toml`의 기본 제한:

| 항목 | 기본값 |
| --- | --- |
| 토론 | 2회 검토, 총 5턴 |
| 모델 호출 | 세션 최대 8회, UTC 날짜당 30회 |
| 참가자 호출 | GPT 5회, Claude 3회, AGY 1회 |
| 시간 | 호출 90초, 세션 누적 실행 600초 |
| 입력 / 응답 | 24,000자 / 6,000자 |
| 프로세스 출력 | stdout·stderr 합계 1 MB |
| 보고 토큰 | 세션 100,000토큰 |
| Claude 호출 예상 비용 | 호출당 0.50 USD |
| 세션 보고·예약 비용 | 2.00 USD |

모델 호출 전에 세션·일일 횟수와 Claude 예약 비용을 하나의 SQLite 트랜잭션으로 기록한다. 실패·중단 때도 호출 횟수와 예약 비용을 되돌리지 않는다. 토큰과 보고 비용은 응답을 받은 뒤 검사하며 초과하면 다음 참가자에게 전달하지 않는다. 프로세스 실패, 인증 실패, 시간·용량 초과, 잘못된 응답, 민감 출력은 오류를 기록하고 멈춘다. 다른 모델로 몰래 바꾸지 않으며 AGY를 대체 호출하지 않는다. 입력·이전 발언을 조용히 자르지도 않는다.

사람의 현재 선호에 따라 새 Work 협업은 성공한 검토·반론·재요청 횟수에 고정 상한을 두지 않는다. 기존 Work에 같은 정책을 적용하거나 실패를 보완할 때는 다음 명령을 쓴다.

```bash
./doro work limits <UUID> --until-quota
./doro work retry <UUID> --instructions work/retry.txt --until-quota
```

이 명령 자체는 호출하지 않는다. 해당 세션에서 누적 횟수·시간·토큰·예상 비용 제한을 풀되 모든 실제 시도는 계속 기록한다. 회당 타임아웃·입출력 크기·공개 입력·현재 승인·AGY 차단은 유지한다. 재요청 범위를 줄일 때만 `--task <공개 JSON>`을 추가하고 원래 실제 입력도 보존한다. Work가 실패 원인을 고쳐 명시적으로 다음 review를 실행하며 구독의 실제 한도 소진이면 멈춘다. 자동 재시도 데몬이나 자동 대체 모델은 아니다. 구독·결제·키 설정은 변경하지 않는다.

금액은 청구 보장이 아니다. Claude의 `--max-budget-usd`는 CLI가 계산한 추정치로, 청구액과 다르거나 한 번의 응답에서 상한을 넘을 수 있다. Codex CLI는 달러 비용을 제공하지 않아 금액을 0으로 기록하지 않는다. 기존 ChatGPT 구독 인증만 확인해 사용하고, 호출·토큰·시간 제한으로 사용을 제한한다. API 키 환경변수와 결제·충전 설정은 사용하거나 변경하지 않는다.

## 권한과 보관

Codex는 전역 설정을 무시하고 read-only 권한으로 실행한다. 쉘·웹 검색·앱·플러그인·훅·하위 에이전트·메모리 사용을 끄고 프로젝트 지침의 자동 읽기를 제한한다. Codex의 기본 작업 지침은 공개 가능한 전용 역할 파일로 대체한다. Claude는 safe/restricted 모드, 빈 도구 목록, 빈 MCP 목록, 훅 비활성화, 자동 허가 거부, 세션 저장 비활성화를 적용한다. 모든 입력은 프로세스 인수 대신 stdin으로 전달하고, 자식 프로세스 환경에는 필요한 기본 변수만 허용한다.

이 설정은 CLI의 권한 기능에 의존한다. CLI 실행 파일 자체를 악성 프로그램으로부터 격리하는 운영체제 수준 보안 컨테이너는 아니다. CLI 버전 변경 후에는 진단과 실제 검증을 다시 수행한다. 기존 CLI 인증 파일, 전역 설정, 연구 저장소, AGY 계정 상태를 수정하지 않는다.

로컬 기록은 `.doro/sessions.sqlite3`, 실행 공간은 `.doro/workspaces/`, 전체 발언 기록은 `.doro/results/<UUID>.md`다. 디렉터리는 700, 데이터·결과 파일은 600 권한으로 만들고 `.doro/`는 Git에서 제외한다. 공개 저장소에는 실행기 소스·공개 예시·오프라인 테스트만 포함한다.

## AGY와 펫 연결의 범위

공개 기본 설정의 AGY는 꺼져 있다. 꺼진 상태에서는 탐지·인증·모델 목록·실행을 하지 않는다. Work의 AGY 활성화는 로컬 모델 설정에서 별도로 허용한다. 기존 Claude 전용 입력 범위는 유지하며 새 공개 Task가 AGY까지 명시적으로 허용해야 한다. GPT Work가 본작업과 최종 판단을 계속 맡고 AGY는 아이디어·부분 검토만 담당한다.

AGY는 검증해 등록한 로컬 `.doro/bin/agy`와 `.doro/agy/verification.json`을 사용한다. 계정·키·결제·전역 설정을 바꾸지 않는다. 매번 새 임시 작업 공간에 공개 에이전트 지침만 만들고 기존 저장소를 연결하지 않는다. 실행 파일 해시·초기 모델·request-review 모드를 확인하며 전역 지침·훅·스킬·에이전트·플러그인이 있거나 도구 사용 이벤트가 나타나면 응답을 채택하지 않고 중단한다. CLI의 초기 도구 등록 목록 자체는 유효 권한의 증거가 아니다. 도구 제한은 해당 CLI 버전의 설정 기능에 의존하며 공개 합성 파일 시험 결과와 한계를 함께 기록한다.

```bash
./doro model --show
./doro model --provider agy --model gemini-4-argon --effort medium --enable
./doro work review <명시적으로-AGY를-허용한-Work-UUID> --provider agy --send
```

모델 설정 저장·조회만으로 호출하지 않는다. `Gemini 4 Argon`과 `medium`은 CLI 슬러그 `gemini-4-argon-medium`으로 해석된다. 검증 파일은 로컬 실행 경계 확인 기록이며 버전 변경 때 다시 확인해야 한다. 검증을 건너뛰려고 직접 만들어서는 안 된다.

전용 도로는 로컬 UI이며 공식 펫 내부에 외부 UI를 삽입하지 않는다. 공식 선택 변경, 실제 화면, UI 입력 도착, 모델 왕복, Quick Chat 중계는 각각 확인한 범위만 보고한다.

## 구조와 검증

화면 조작 뒤 포인터 잔상이 남는 Mac에서는 `python3 tools/install_cursor_cleanup.py`로 종료 정리를 설치할 수 있다. Mac의 특정 SDK를 써야 하면 `--sdk <SDK 경로>`를 붙인다. 설치 후 Codex `/hooks`에서 새 훅을 검토·신뢰해야 자동 실행된다. 설치기는 신뢰 상태나 기존 훅을 바꾸지 않는다.

화면 조작 시작을 등록하고, 작업 종료·중단·CUA reset 때 사용권을 해제한다. 다른 화면 작업의 사용권이 남아 있으면 공용 보조 앱 종료를 미루고 경고한다. `lifecycle.py status`는 남은 사용권과 포인터 수를 보여준다. 실제 종료·중단을 확인한 세션의 오래된 사용권만 `lifecycle.py release-ended --session <UUID>`로 해제한다. 모든 등록된 사용이 끝나면 이전부터 남은 잔상도 정리한다. 정리 대상은 실제 `Software Cursor` 창을 소유한 로컬 화면 조작 보조 프로세스이며, 실행 파일 경로를 대조한 뒤 정상 종료 신호만 보낸다. 상주 감시·추가 모델 호출·계정 변경은 없다. 지원되는 로컬 훅이 적용되지 않는 ChatGPT 환경에서는 종료 훅 자동 실행을 보장하지 않는다.

대화창 본문·빈 공간을 드래그하면 이동한다. 숨긴 창을 다시 열면 메뉴 막대 아래로 돌아온다. 메뉴 막대 아이콘을 다시 누르면 초안을 유지한 채 창만 숨기며 메뉴 막대의 종료 메뉴는 UI 앱을 종료한다. 실행 중인 Work와 기록은 보존하고 새 입력만으로 숨긴 창을 자동으로 띄우지 않는다.

대화 목록은 작업 행을 한 번에 최대 3개 높이로 보여 주고 나머지는 같은 목록에서 세로 스크롤로 찾는다. 지난 대화를 펼쳐도 이 상한을 유지하며 지난 대화·선택·삭제 취소는 스크롤 밖에서 조작한다. 창·말풍선·입력·설정·승인창은 macOS의 라이트/다크 모드를 자동으로 따른다. 시스템 Night Shift 설정은 변경하지 않는다.

진행 중·승인 대기·입력 전달 중 작업을 먼저 표시하고 끝난 작업과의 경계에 구분선을 넣는다. 열린 대화라도 완료된 작업은 뒤쪽으로 분류한다. 지난 대화가 펼쳐지면 ↑, 접히면 ↓로 표시한다. 바깥 앱·바탕화면을 누르면 대화와 접힌 dock을 모두 숨기고 메뉴 아이콘만 유지한다.

승인/보류 답변이 저장되면 질문 창을 닫고 답변을 대화에 남긴다. 아직 답하지 않은 질문만 승인 수에 포함한다. 실패한 전송은 창을 유지해 다시 시도할 수 있다. 접수는 파일 반영 완료를 뜻하지 않는다. 내 채팅과 승인 답변은 오른쪽, GPT·Claude 발언은 왼쪽이다. 위쪽 대화를 읽을 때 새 답변이 와도 읽던 위치를 유지한다.

창 수명 정책이 켜져 있으면 메뉴 아이콘이 남은 숨김·dock 상태는 협업을 유지한다. 메뉴의 종료·충돌로 창의 OS 잠금이 풀리면 외부 호출을 프로세스 경계에서 중단하고 새 호출도 차단한다. 창을 다시 열어도 중단된 호출은 자동 재개하지 않는다. `./doro window policy`로 정책과 실제 실행 상태를 조회한다. 같은 프로젝트의 다른 창 인스턴스가 이전 호출을 되살리지 못하도록 소유 파일의 교체도 확인한다. 공개 입력·참가자별 설정·승인 경계는 그대로 적용한다.

대기 중에는 로컬 파일 변경만 확인하며, 변경된 경우에만 읽기 실행기를 호출한다. 변경이 없는 동안은 30초 안전 조회를 하고, 숨김·dock에서는 대화 본문을 읽지 않는다. 최근 본문 캐시는 세 대화로 제한하되 초안·읽던 위치는 별도로 보존한다. 중복 타이머 시작을 막고, 로컬 읽기·설정 명령에는 15초 대기 한도를 둔다. 설정 저장 성공은 팝오버를 닫고 실패는 오류를 남긴다. 이 조회는 모델 생성이 아니다.

의존 방향은 `domain` ← `application` / `infrastructure` ← `interface`다. 도메인의 타입과 정책을 공용 출처로 쓰고 애플리케이션은 프로세스·저장소 포트에만 의존한다. CLI가 실제 저장소·어댑터를 조립한다. 재수출 모듈은 없다.

공용 자료함의 변경 감시기는 `python3 tools/install_shared_radar.py --connection <연결.json> --automation <기존 automation.toml>`로 설치한다. 기존 연결 JSON의 두 Page와 기존 Work 소유자를 사용한다. 로컬 확인은 1분마다, Space 메타데이터 확인은 30분마다 수행하며, 변경이 없으면 Work 메시지를 만들지 않는다. 기존 Work 주기 예약은 중지해 둔다.

Space 확인은 공식 app-server의 임시 연결에서 `read_page(include_content=false)`만 호출한다. 모델 생성 턴은 실행하지 않으며 사용자 대화나 API 키를 새로 만들지 않는다. 실제 새 버전·미전송 파일 해시가 있을 때만 기존 Work에 알린다. 같은 변경은 재실행·재시작 후에도 한 번만 전송하며, 결과가 불확실한 큐 전달은 자동 재시도하지 않는다. Obsidian이 중지돼 있거나 접근·버전 확인에 실패하면 Work를 대체 호출하지 않고 로컬 상태에 오류를 남긴다.

감시기의 전달 장부와 마지막 상태는 로컬 설치 폴더에만 둔다. 원문의 동기화 정본은 기존 플러그인의 `shared-state.json`이며 감시기가 수정하지 않는다. Mac 로그인 세션·Codex 연결 도구·Obsidian이 사용 가능해야 한다. 설치 뒤 `python3 -m doro.interface.shared_radar --config <감시기 설정> --status`로 큐 접수 기록을 확인할 수 있다. 큐 접수와 실제 Work 반영은 별도 상태다.

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
python3 tools/check_architecture.py
ruff check .
mypy
```

개발 검사에만 `ruff==0.17.0`, `mypy==2.4.0`가 필요하다. CI는 순환 의존성, 레이어 경계, 220줄 파일·65줄 함수·3단계 중첩, 복잡도, strict 타입과 행동 테스트를 검사한다. 오프라인 테스트는 개인 계정이나 실제 모델을 호출하지 않는다.

설계 참고: [CodePet의 공유 채팅·턴 제어](https://github.com/nokryong/CodePet/blob/main/README.md), [Codex 비대화형 실행](https://learn.chatgpt.com/docs/developer-commands#codex-exec), [Codex 설정](https://learn.chatgpt.com/docs/config-file/config-reference), [Claude CLI 옵션](https://code.claude.com/docs/en/cli-reference), [AGY 응답 계약](https://antigravity.google/docs/cli/headless/), [ChatGPT 펫](https://learn.chatgpt.com/docs/pets), [활동·알림](https://learn.chatgpt.com/docs/notifications). CodePet은 다양한 계정·대화·펫 기능을 제공한다. 이 작업에서는 계정 전환·대화 감시 없이 GPT 최종 판단과 공개 입력 제한을 유지하기 위해 독립 실행기를 선택했다.

### 작업 중 협업창 입력 알림

기본 전달은 공식 `codex queue`다. 작업 중에도 다음 도구 실행 뒤 입력 ID를 확인하도록 공식 `PostToolUse` 알림을 추가할 수 있다. 설치된 Doro 스킬이 있는 환경에서 아래 명령은 설정안을 보여주며, `--apply`를 붙이면 기존 후크를 보존하고 한 항목을 추가한다. 변경 전 파일은 Codex의 `skill-archives`에 보관한다.

```sh
python3 tools/install_input_notifications.py
python3 tools/install_input_notifications.py --apply
```

새 후크는 Codex CLI의 `/hooks`에서 정의를 검토하고 정상적으로 신뢰한 뒤에만 실행된다. 설치 도구는 신뢰 기록을 수정하지 않는다. [공식 후크 문서](https://learn.chatgpt.com/docs/hooks)를 따른다. 후크 설정을 읽는 다음 실행/재개 전에는 현재 작업에 활성화됐다고 단정하지 않는다.

후크는 공식 이벤트의 `session_id`를 등록된 소유 Work와 대조해 입력 ID만 최대 5개씩 알려주고, 원문·도구 결과는 출력하거나 저장하지 않는다. 셸 도구의 `CODEX_THREAD_ID` 환경변수는 후크 실행에 보장되지 않으므로 필수로 요구하지 않으며, 제공된 경우에는 이벤트의 세션 ID와도 일치해야 한다. 공식 후크가 하위 에이전트에 붙이는 `agent_id` 또는 `agent_type` 필드가 있으면 값에 관계없이 알림을 차단한다. 같은 turn에서는 같은 ID를 다시 알리지 않으며, 아직 처리하지 않은 입력은 다음 turn에서 다시 알릴 수 있다. 보조 알림만으로 입력을 읽음·승인·완료 처리하거나 새 모델을 호출하지 않는다. 기존 queue는 쉬는 Work의 시작 경로로 유지된다. 표식을 받은 실제 주 작업도 자기 thread ID와 소유자가 일치할 때만 원문을 읽는다.

`inputs get`과 `inputs pending`/`wait`의 소유자 검증을 통과한 최초 조회가 `도로 확인`을 기록한다. 최종 답변은 별도 `inputs ack`로 남긴다. `inputs get`의 `timing`은 저장·queue 접수·보조 알림 생성·원문 조회·최종 답변의 Unix 시각이다. 이전 자료의 없는 시각은 `null`로 남기며 과거 지연을 추정하지 않는다. 이는 시스템 시계 기록으로, 시계가 조정된 구간의 차이를 정밀 지연으로 해석하지 않는다. 도구가 끝나지 않는 동안과 후크가 비활성인 환경의 대기열 지연은 이 알림만으로 없앨 수 없다.
