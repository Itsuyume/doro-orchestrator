# 도로 CLI 오케스트레이터

프로젝트 대화의 GPT Work가 본작업과 최종 판단을 맡고, 사용자가 요청할 때 Claude Code와 검토·반론·보완을 주고받는다. 기존 Codex CLI 중심 실행 모드도 유지한다. AGY의 기본값은 `enabled = false`이며 꺼진 참가자는 버전·인증·모델 목록 확인도 실행하지 않는다.

## 프로젝트에서 요청할 때만 협업하기

```bash
python3 tools/install_work_skill.py
```

설치기는 `~/.codex/skills/doro-orchestration/`에 개인 스킬을 만들고 `~/.codex/skill-docs/doro-orchestration.json`에 이 실행기 위치를 등록한다. 다른 설치본이나 사용자 수정이 있으면 덮어쓰지 않는다. 설치 후 프로젝트의 **Work 대화에서** “도로, 오케스트레이션 시작해줘” 또는 “Claude와 같이 검토해줘”라고 요청한다. 명시적으로 스킬을 고를 때는 `$doro-orchestration`을 사용한다. 새 스킬이 보이지 않으면 앱의 스킬 목록을 새로고침하거나 새 대화에서 확인한다.

일반 프로젝트 작업·질문·펫 표시·상태 확인은 협업을 시작하지 않는다. 요청을 받으면 현재 Work가 초안을 만들고 Claude의 실제 검토를 읽어 보완한다. 필요할 때 검토를 더 요청하고 현재 Work가 최종 결과를 기록·통합한다. 검토·상호작용 횟수의 고정 상한은 없다. 별도 Codex CLI를 메인으로 중복 실행하지 않는다. 작업 파일이나 전체 대화를 자동 수집하지 않는다.

스킬은 `work start`(로컬 초안 저장, 호출 없음), `work review --send`(Claude 호출), `work reply`(Work 보완), `work finish`(Work 최종 판단), `work status`(호출 없는 조회)를 사용한다. 검토 한 번으로 충분하면 일찍 마무리할 수 있다. 두 실행 모드는 외부 호출 코드와 SQLite 장부를 공유한다. 새 Work 협업에는 누적 횟수·토큰·시간·추정 비용 상한을 두지 않으며, 독립 CLI와 `work start --bounded`는 기존 제한을 쓴다. Work 모드의 보고 토큰·비용은 외부 Claude 호출만 포함하며 현재 Work 대화 자체의 사용량은 포함하지 않는다.

### 진행 중 관찰과 승인

Work 협업은 **시작 범위·중요 분기·실제 파일 반영 전**에 사용자 결정을 기다린다. `work start`는 `awaiting_approval`로 저장하며 Claude 인증 확인이나 모델 호출을 시작하지 않는다. 현재 Work가 전달할 구체적인 입력과 범위를 대화에 제시하고 사용자 입력 도구로 질문한다. 사용자의 실제 답이 오면 현재 체크포인트 ID에 결정을 기록한다. 이미 받은 구체적인 동일 범위의 승인은 재사용한다. 승인된 범위 안의 모든 검토 턴마다 질문을 반복하지 않는다.

```bash
./doro work decide <UUID> --checkpoint <현재-체크포인트-ID> --decision approve
./doro work review <UUID> --send
./doro work checkpoint <UUID> --kind branch --summary work/branch.txt
./doro work checkpoint <UUID> --kind apply --summary work/proposed-change.txt
```

`decide`는 신뢰되는 현재 Work 또는 사용자의 로컬 명령이 내리는 결정을 기록한다. 사람 신원을 독립적으로 인증하는 보안 장치는 아니므로 Work가 실제 사용자 답을 확인해야 한다. Claude 출력·기본 선택·시간 경과는 승인이 아니다. 오래된 ID·중복 응답은 거부하고, 대기 중에는 다음 모델 호출·Work 보완·완료를 거부한다. `--decision reject`는 `awaiting_direction`에서 멈추고, 수정된 같은 종류의 체크포인트를 다시 승인하기 전에는 진행하지 않는다. 기존 v1/v2 세션은 조회할 수 있지만 과거 기록을 새 승인으로 간주하지 않는다.

중요 분기의 의미를 판단하고 필요한 체크포인트를 여는 일은 현재 Work의 책임이다. `work finish`는 최종 발언만 기록한다. 실행기는 프로젝트 파일을 수정하지 않으며, 실제 파일 반영 승인과 반영·검증은 현재 Work가 책임진다. 따라서 실행기가 현재 Work의 모든 파일 접근을 운영체제 수준에서 차단한다고 보장하지 않는다.

진행은 공식 펫 옆에서 쓰는 macOS 대화창에서 볼 수 있다. GPT와 Claude의 실제 발언은 왼쪽, 사용자 입력은 오른쪽이다. 중립적인 흰색·회색 말풍선을 쓰고 긴 발언은 펼쳐 본다. 새 창은 기본 390×590 포인트이며 대화 부분을 스크롤한다. Claude/AGY 점은 협업 참여 켜짐·꺼짐을 뜻하며 인증·구독 잔여량 표시가 아니다. 공식 펫과 이미지는 그대로 둔다.

모델 응답을 기다리지 않고 열려면 **도로협업.app**을 누르거나 작업창 실행 중 **⌃⌥D(Control+Option+D)**를 누른다. 메뉴 막대 말풍선을 누르면 그 아래에 작업 목록이 열리며, 다시 누르면 창만 숨긴다. 우클릭·Control 클릭으로 작업 목록·숨기기·종료 메뉴를 연다. 앱을 완전히 종료하면 전역 단축키도 해제되므로 바로가기 앱으로 다시 실행한다. 단축키 충돌이 감지되면 창에 안내하고 다른 앱의 단축키를 빼앗지 않는다. 시스템 예약 단축키의 모든 충돌을 감지하지는 못한다.

로컬 바로가기 설치는 다음 명령을 쓴다. 네이티브 창을 미리 빌드하고 `~/Applications/도로협업.app`을 만든다. Dock·Spotlight에서 사용할 수 있으며 Work·모델 호출·계정 변경 없이 기존 창을 연다. 로그인 시 자동 실행 설정은 바꾸지 않는다.

```bash
python3 -m tools.install_window_shortcut
```

공식 펫 입력창에서 **“오케스트레이션 켜줘”**, **“도로 협업창 켜줘”**라고 하면 설치된 스킬은 검색·새 Work 생성보다 로컬 창 열기를 먼저 실행한다. 자동 선택이 안 되면 **`$doro-orchestration 협업창 켜줘`**로 요청한다. 공식 닷츠의 자연어 입력을 모델보다 먼저 로컬 명령으로 처리하는 연결은 구현되지 않았다. 자연어 요청은 Chat/Work 응답 지연이 남을 수 있으므로 즉시 열기는 바로가기·단축키를 쓴다.

```bash
./doro window open
./doro window open --session <등록된-UUID>
./doro window minimize
./doro window hide
./doro chat <UUID> --display panel
./doro chat <UUID> --text
./doro inputs pending <UUID> --owner-thread <소유-Work-ID>
./doro inputs wait <UUID> --owner-thread <소유-Work-ID> --timeout 55
./doro inputs ack <입력-ID> --owner-thread <소유-Work-ID> --response work/reply.txt
```

`−`는 창을 숨기고 메뉴 아이콘을 남긴다. `×`는 UI 앱을 종료해 아이콘도 제거하며 원래 GPT Work·실행 기록은 유지한다. Spotlight(Command+Space)에서 **도로협업**을 검색해 다시 연다. 대화 왼쪽 위 `‹`로 작업 목록에 돌아간다. 입력 초안과 읽은 위치는 실행 중 작업별로 보관한다. 목록 행의 `×`는 그 항목만 닫는다. 가장자리·여백·본문에서 끌어 창을 옮기고 입력칸과 스크롤바는 원래 조작을 유지한다. 말풍선은 우클릭으로 복사한다. 다른 작업의 메시지 전달 중에도 종료 버튼·메뉴는 잠시 비활성화된다.

닫힌 작업과 지난 대화는 휴지통으로 하나씩 지우거나 `⋯`에서 선택·전체 지우기를 쓴다. 목록 표시만 지우고 원래 GPT 대화·실행 기록은 보존한다. 진행·승인·답변 대기 항목은 지우지 않는다. 마지막 삭제 묶음의 되돌리기와 삭제 상태는 재실행 후에도 유지하며 새 승인이 생기면 해당 작업을 다시 표시한다. 로컬 `.doro/native/stack-history.json`에는 항목 ID만 저장한다. 작업 목록 창은 펼친 내용 높이에 맞춰 줄고 늘며, 길어지면 최대 높이에서 스크롤된다. 대화창 크기는 따로 보존한다.

창을 열 때 메뉴 아이콘 아래에 놓고 화면의 남는 영역에 맞춘다. 드래그한 뒤에는 그대로 유지하며 숨겼다가 다시 열면 메뉴 막대 아래로 돌아온다. 폴링만으로 창을 다시 배치하지 않는다. 공식 펫 좌표를 읽거나 펫 위치에 따라 자동 이동하지 않는다.

공식 펫과 원본 이미지는 그대로 둔다. 기본 대화창은 `--display panel`이며 추가 캐릭터나 자동 교대를 쓰지 않는다.

대화 입력과 별도 승인/보류 버튼은 정확한 세션·소유 Work·현재 질문에 묶인다. UI 토큰 검증 뒤 입력과 전달 대기를 함께 저장하고, 공식 [`codex queue`](https://learn.chatgpt.com/docs/developer-commands#codex-queue)로 기존 Work UUID에 ID 표식만 넣는다. Work가 이를 받아 실제 입력을 확인한 뒤 답하고, 현재 질문에만 결정한다. 입력 원문과 토큰은 프로세스 인자나 Claude에 자동 전달하지 않는다. 앱 자체의 도구 권한은 이 버튼으로 대신 승인하지 않는다.

같은 입력은 한 번만 송신한다. 큐 접수는 실제 Work 수신·파일 반영과 구분한다. 확정 실패에는 ‘다시 보내기’를 제공하고 불확실한 전송은 자동 반복하지 않는다. Codex 앱이 실행 중이어야 하며 실제 수신·답변이 확인돼야 재개 성공이다. 별도 Codex 메인 작업을 실행하지 않는다.


설정 아이콘에서 작업별 Claude 모델과 생각 수준을 선택한다. 다음 검토부터 적용하며 저장만으로 호출하지 않는다. 실제 응답 모델은 반환 메타데이터로 표시한다. 로컬 기본값 예:

```bash
./doro model --model claude-opus-5-5 --effort medium
```

Claude는 세션 저장을 끄고 도구를 제한해 실행한다. Claude 대화 목록에 별도 세션을 저장하지 않으며 로컬 실행기가 실제 입력·응답을 이어 간다. 원래 GPT 대화에도 전달 범위, 실제 검토 요지, GPT 판단과 결과를 남긴다. 실제 구독 소비·응답 모델은 호출 결과에 근거해 보고한다. 기존 `pet-swap`·`--display integrated` 명령은 호환성을 위해 보존하며 별도 명시 요청 전에는 사용하지 않는다.

macOS SDK가 현재 Swift 도구와 맞지 않아 빌드가 실패할 경우 호환되는 SDK의 절대 경로를 로컬 `.doro/native/sdk-path` 한 줄에 지정할 수 있다. 지정한 경로가 없으면 명확히 실패하며 임의 대체하지 않는다. 이 파일은 개인 설정이며 Git에 넣지 않는다.

## 실행

Python 3.11 이상, PATH에 설치된 `codex`와 `claude`, 기존 구독 계정 로그인이 필요하다. 실행기 자체에는 추가 Python 패키지가 필요 없다. 프로젝트 폴더에서 실행한다.

```bash
./doro doctor
./doro plan --task examples/smoke.json
./doro run --task examples/smoke.json --send
```

`run`도 `--send`가 없으면 전달할 입력과 계획만 보여준다. 새 작업은 예시 JSON을 복사해 `message`와 `context`에 **외부 모델에 전달해도 되는 내용만 직접** 작성한다. `classification: "public"`과 수신 모델 목록을 명시해야 한다. 저장소, 문서, 대화 내역, 파일 첨부를 자동 수집하는 기능은 없다. 비공개 입력은 거부된다. 인식할 수 있는 키·토큰·이메일·개인 절대 경로도 검사한다. 이 검사는 모든 형태의 개인정보를 판별하는 분류기가 아니므로 공개 여부는 작성자가 확인한다.

```bash
./doro show <출력된-세션-UUID>
./doro resume <출력된-세션-UUID> --send
```

실패한 세션은 자동 재시도하지 않는다. 명시적 `resume`은 완료된 턴을 건너뛰고 실패한 단계부터 이어 간다. 이전 호출·예약 비용·사용량은 유지한다. 설정이나 역할 지침이 바뀌면 기존 세션 재개를 거부한다. 실행 중에는 Ctrl+C로 중단한다. 진행 중인 프로세스 그룹을 종료하고 세션을 `interrupted`로 기록한다. 같은 세션의 동시 실행도 거부한다.

## 역할과 전달 흐름

기본 흐름은 GPT 초안 → Claude 검토 → GPT 반론·보완 → Claude 재검토 → GPT 최종 판단이다. 각 참가자는 이전 발언 전체를 명시적 텍스트 기록으로 받는다. Claude가 낸 제안과 반론은 GPT가 검토해 채택·기각 이유를 설명한다. `@codex` 같은 문자열은 발언의 일부이며 임의 호출이나 권한 확대를 일으키지 않는다. 모델 출력의 명령·코드를 자동 실행하거나 프로젝트에 자동 적용하지 않는다. GPT는 본작업의 코드·패치·해답을 만들며 결과 적용은 메인 작업 세션이 검토한 뒤 수행한다.

`roles/codex.md`, `roles/claude.md`, `roles/agy.md`가 역할의 단일 출처다. CLI 자체의 대화를 재개하지 않고 매번 새로운 제한된 프로세스를 실행한다. 실행기가 SQLite 세션 기록과 턴 순서를 책임지므로 다른 프로젝트의 최근 대화가 섞이지 않는다. 실제 CLI의 응답 세션 ID도 각 턴에 기록한다.

## 제한과 실패 처리

독립 CLI 모드와 `work start --bounded`에서 사용하는 `orchestrator.toml`의 기본 제한:

| 항목 | 기본값 |
| --- | --- |
| 토론 | 2회 검토, 총 5턴 |
| 모델 호출 | 세션 최대 8회, UTC 날짜당 30회 |
| 참가자 호출 | GPT 5회, Claude 3회, AGY 1회 |
| 시간 | 호출 90초, 세션 누적 실행 600초 |
| 입력 / 응답 | 24,000자 / 6,000자 |
| 프로세스 출력 | stdout·stderr 합계 1 MB |
| 보고 토큰 | 세션 100,000토큰 |
| Claude 호출 예상 비용 | 호출당 0.50 USD |
| 세션 보고·예약 비용 | 2.00 USD |

모델 호출 전에 세션·일일 횟수와 Claude 예약 비용을 하나의 SQLite 트랜잭션으로 기록한다. 실패·중단 때도 호출 횟수와 예약 비용을 되돌리지 않는다. 토큰과 보고 비용은 응답을 받은 뒤 검사하며 초과하면 다음 참가자에게 전달하지 않는다. 프로세스 실패, 인증 실패, 시간·용량 초과, 잘못된 응답, 민감 출력은 오류를 기록하고 멈춘다. 다른 모델로 몰래 바꾸지 않으며 AGY를 대체 호출하지 않는다. 입력·이전 발언을 조용히 자르지도 않는다.

사람의 현재 선호에 따라 새 Work 협업은 성공한 검토·반론·재요청 횟수에 고정 상한을 두지 않는다. 기존 Work에 같은 정책을 적용하거나 실패를 보완할 때는 다음 명령을 쓴다.

```bash
./doro work limits <UUID> --until-quota
./doro work retry <UUID> --instructions work/retry.txt --until-quota
```

이 명령 자체는 호출하지 않는다. 해당 세션에서 누적 횟수·시간·토큰·예상 비용 제한을 풀되 모든 실제 시도는 계속 기록한다. 회당 타임아웃·입출력 크기·공개 입력·현재 승인·AGY 차단은 유지한다. 재요청 범위를 줄일 때만 `--task <공개 JSON>`을 추가하고 원래 실제 입력도 보존한다. Work가 실패 원인을 고쳐 명시적으로 다음 review를 실행하며 구독의 실제 한도 소진이면 멈춘다. 자동 재시도 데몬이나 자동 대체 모델은 아니다. 구독·결제·키 설정은 변경하지 않는다.

금액은 청구 보장이 아니다. Claude의 `--max-budget-usd`는 CLI가 계산한 추정치로, 청구액과 다르거나 한 번의 응답에서 상한을 넘을 수 있다. Codex CLI는 달러 비용을 제공하지 않아 금액을 0으로 기록하지 않는다. 기존 ChatGPT 구독 인증만 확인해 사용하고, 호출·토큰·시간 제한으로 사용을 제한한다. API 키 환경변수와 결제·충전 설정은 사용하거나 변경하지 않는다.

## 권한과 보관

Codex는 전역 설정을 무시하고 read-only 권한으로 실행한다. 쉘·웹 검색·앱·플러그인·훅·하위 에이전트·메모리 사용을 끄고 프로젝트 지침의 자동 읽기를 제한한다. Codex의 기본 작업 지침은 공개 가능한 전용 역할 파일로 대체한다. Claude는 safe/restricted 모드, 빈 도구 목록, 빈 MCP 목록, 훅 비활성화, 자동 허가 거부, 세션 저장 비활성화를 적용한다. 모든 입력은 프로세스 인수 대신 stdin으로 전달하고, 자식 프로세스 환경에는 필요한 기본 변수만 허용한다.

이 설정은 CLI의 권한 기능에 의존한다. CLI 실행 파일 자체를 악성 프로그램으로부터 격리하는 운영체제 수준 보안 컨테이너는 아니다. CLI 버전 변경 후에는 진단과 실제 검증을 다시 수행한다. 기존 CLI 인증 파일, 전역 설정, 연구 저장소, AGY 계정 상태를 수정하지 않는다.

로컬 기록은 `.doro/sessions.sqlite3`, 실행 공간은 `.doro/workspaces/`, 전체 발언 기록은 `.doro/results/<UUID>.md`다. 디렉터리는 700, 데이터·결과 파일은 600 권한으로 만들고 `.doro/`는 Git에서 제외한다. 공개 저장소에는 실행기 소스·공개 예시·오프라인 테스트만 포함한다.

## AGY와 펫 연결의 범위

AGY는 현재 호출하지 않는다. `enabled = false`는 탐지·인증·실행보다 먼저 검사한다. AGY의 CLI 설치·모델 접근·권한 계약과 실제 응답은 검증하지 않았다. IDE가 설치되어 있어도 CLI가 있다는 뜻은 아니다. 향후 AGY를 사용할 때는 인증·권한 확인을 먼저 구현·검증해야 하며, 현재 진단은 AGY 활성화 시 준비되지 않았다는 오류로 중단한다. `enabled`를 바꾸는 것만으로 동작을 보장하지 않는다.

전용 도로는 로컬 UI이며 공식 펫 내부에 외부 UI를 삽입하지 않는다. 공식 선택 변경, 실제 화면, UI 입력 도착, 모델 왕복, Quick Chat 중계는 각각 확인한 범위만 보고한다.

## 구조와 검증

화면 조작 뒤 포인터 잔상이 남는 Mac에서는 `python3 tools/install_cursor_cleanup.py`로 종료 정리를 설치할 수 있다. Mac의 특정 SDK를 써야 하면 `--sdk <SDK 경로>`를 붙인다. 설치 후 Codex `/hooks`에서 새 훅을 검토·신뢰해야 자동 실행된다. 설치기는 신뢰 상태나 기존 훅을 바꾸지 않는다.

화면 조작 시작을 등록하고, 작업 종료·중단·CUA reset 때 사용권을 해제한다. 다른 화면 작업이 남아 있거나 시작 전에 이미 존재한 포인터가 있으면 공용 보조 앱 종료를 미룬다. 정리 대상은 실제 `Software Cursor` 창을 소유한 로컬 화면 조작 보조 프로세스이며, 실행 파일 경로를 대조한 뒤 정상 종료 신호만 보낸다. 상주 감시·추가 모델 호출·계정 변경은 없다. 지원되는 로컬 훅이 적용되지 않는 ChatGPT 환경에서는 종료 훅 자동 실행을 보장하지 않는다.

대화창 본문·빈 공간을 드래그하면 이동한다. 숨긴 창을 다시 열면 메뉴 막대 아래로 돌아온다. −는 초안을 유지한 채 창만 숨기며 ×는 UI 앱을 종료한다. 실행 중인 Work와 기록은 보존하고 새 입력만으로 숨긴 창을 자동으로 띄우지 않는다.

승인/보류 답변이 저장되면 질문 창을 닫고 답변을 대화에 남긴다. 아직 답하지 않은 질문만 승인 수에 포함한다. 실패한 전송은 창을 유지해 다시 시도할 수 있다. 접수는 파일 반영 완료를 뜻하지 않는다. 내 채팅과 승인 답변은 오른쪽, GPT·Claude 발언은 왼쪽이다. 위쪽 대화를 읽을 때 새 답변이 와도 읽던 위치를 유지한다.

의존 방향은 `domain` ← `application` / `infrastructure` ← `interface`다. 도메인의 타입과 정책을 공용 출처로 쓰고 애플리케이션은 프로세스·저장소 포트에만 의존한다. CLI가 실제 저장소·어댑터를 조립한다. 재수출 모듈은 없다.

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
python3 tools/check_architecture.py
ruff check .
mypy
```

개발 검사에만 `ruff==0.17.0`, `mypy==2.4.0`가 필요하다. CI는 순환 의존성, 레이어 경계, 220줄 파일·65줄 함수·3단계 중첩, 복잡도, strict 타입과 행동 테스트를 검사한다. 오프라인 테스트는 개인 계정이나 실제 모델을 호출하지 않는다.
