# 기존 시작 범위의 구성 불일치 복구

`Configuration or role instructions changed`는 승인 누락과 다르다. 모델 호출을 중단하고 `work status <세션>`의 `stored_fingerprint`, `current_fingerprint`, `session_sha256`과 실제 설정·역할 변경 내역을 대조한다. 설정·역할을 되돌리거나 지문을 직접 고쳐 검사를 통과시키지 않는다.

사용자가 기존 세션 복구를 명시적으로 요청했고, 같은 소유 Work의 아직 미해결인 시작 질문과 승인된 공개 자료를 확인한 경우에만 다음 절차를 쓴다. 같은 구체적 범위의 사람 승인을 이미 받았으면 다시 묻지 않는다. 그 승인과 정확한 질문 ID를 보존한다. 불명확한 권한 확대·참가자 추가·검토 회수 변경은 이 복구 범위가 아니다.

1. 대상 세션·소유자·질문·원래 초안·입력·작업 기록을 로컬에 보관한다. 현재 등록된 `CODEX_THREAD_ID`가 소유자와 같아야 한다. 개인 노트·계정·다른 대화는 복구 입력에 추가하지 않는다.
2. 사람이 승인한 공개 task JSON과 초안 파일의 실제 바이트 SHA-256을 확인하고, 복구 이유를 짧은 UTF-8 파일에 적는다. 현재 구성과 전체 세션 상태의 해시는 위 status 결과를 사용한다.
3. 등록된 bridge에서 다음 명령을 실행한다. `<...>`는 관측한 값이며 임의로 만들지 않는다.

```text
work recover <세션> --owner-thread <현재 Work UUID>
  --checkpoint <현재 시작 질문 UUID>
  --expected-state <session_sha256> --expected-config <current_fingerprint>
  --task <승인된 공개 JSON> --task-sha256 <그 파일의 바이트 해시>
  --draft <승인된 공개 초안> --draft-sha256 <그 파일의 바이트 해시>
  --reason <복구 이유 파일>
```

명령은 한 줄로 실행한다. 복구는 원래 task를 별도 이력에, 원래 초안을 기존 발언에 보존하고 새 공개 초안을 revision으로 추가한다. 승인 질문·기존 결정·호출·비용·작업 상태는 초기화하지 않는다. 다음 외부 입력에는 복구 후 공개 초안부터 사용하며 예전 초안·로컬 승인 메시지를 몰래 합치지 않는다. 복구 자체는 승인 결정이나 외부 호출이 아니다.

4. 재조회해 원래 질문이 그대로이며 구성 일치가 참인지, 복구 이력이 한 건만 추가됐는지 확인한다. 실제 사람이 답한 기존 질문의 승인을 `work decide`로 기록한 뒤 허용된 `work review --send`를 실행한다. 이미 성공한 검토를 다시 보내지 않으며 사용자가 정한 호출 횟수를 지킨다.

현재 명령은 미해결 시작 범위의 복구만 지원한다. 실행 중·완료·취소·거절 상태, 다른 소유 Work, 바뀐 입력 해시·상태·구성, 참가자 확대, 검토 회수 변경은 오류로 남긴다. 지원하지 않는 상태를 직접 바꾸거나 새 세션으로 우회하지 않는다. 나중에 구성이 다시 바뀌면 새 관측과 명시적 복구가 필요하다.
