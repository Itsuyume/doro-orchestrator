# 전용 도로 펫에서 진행과 입력 처리

`bridge.py chat <session_id>`의 기본값은 마스코트 없는 macOS 대화 패널이다. 한 도로 통합은 [공식 교대](pet-swap.md)를 완료한 뒤 `--display integrated`로 연다. 원본 도로 스프라이트를 로컬에서 읽고 외부에 업로드하거나 공개 저장소에 복사하지 않는다. 대화·입력·승인은 도로와 함께 움직인다. `−` 최소화는 작은 작업 스택을 남기고, `×` 닫기는 그 대화를 스택에서 뺀다. 둘 다 도로와 실제 작업·승인 질문은 유지한다. 닫힌 대화는 ‘작업 목록’에서 다시 연다. 공식 복귀는 별도 메뉴다. GPT와 Claude의 발언은 왼쪽, 사람의 입력만 오른쪽이다. 긴 발언은 펼칠 수 있고 실제 외부 입력은 별도 보기로 확인한다.

작은 스택이나 ‘작업 목록’에서 작업을 고르면 현재 본문을 숨기고 선택한 협업만 표시한다. 지난 검증·완료 기록을 기능 탭처럼 기본 노출하지 않는다. 등록된 로컬 협업의 이름·상태·대기 수만 사용하며 다른 Work 대화를 검색하지 않는다. 입력 초안·읽은 위치·펼친 발언을 스택별로 보관한다. 전송 중 스택을 바꿔도 입력은 캡처한 목적지에만 도착한다. 접힌 도로에는 전체 승인 수만 표시하며 보지 않은 질문을 일괄 승인하지 않는다. Claude·AGY는 설정의 enabled에 따라 초록/회색 점만 표시한다. 실시간 인증·응답 중 상태나 구독 잔여량이 아니다. 스택 선택·닫기·읽기·초안 작성은 모델 호출이 아니다.

## 승인창과 모델 선택

승인은 일반 말풍선이나 입력칸에 긴 설명을 붙이지 않고 별도 작은 창에 표시한다. 체크포인트 생성 시 `--brief <280자 이내 파일>`로 대상·범위·영향을 직접 작성하고 `--summary`에는 원문과 검증 근거를 보존한다. 요약을 임의로 자르거나 자동 생성하지 않는다. 요약 없는 이전 질문은 상세를 기본으로 펼친다.

질문은 같은 ID당 한 번만 자동 표시한다. 최소화 중에는 승인 수만 표시하고, ‘승인’ 목록에서 정확한 작업을 골라 다시 연다. 나중에·닫기·Escape는 결정을 기록하지 않는다. 보류는 실행기의 `reject`이며 현재 변경을 적용하지 않고 사용자 방향을 기다리는 뜻이다. 승인/보류 답변을 큐에 넣은 뒤 실제로 접수된 선택과 Work 확인 대기를 표시한다. 같은 질문에 두 번째 결정을 넣지 않으며, 일반 채팅은 별도로 쓸 수 있다. 다른 작업으로 바꾸면 기존 승인창을 닫는다.

승인/보류가 로컬 큐에 저장되면 해당 질문 창은 즉시 닫고, 질문 수에서도 제외한다. 실제 답변과 Work 확인 상태는 대화에 남는다. 저장 실패 시에는 창과 오류를 유지한다. 접수와 실제 파일 적용을 같은 완료로 표시하지 않는다. 이미 답한 질문은 재팝업하지 않는다. 사용자가 승인 목록에서 직접 질문을 열었을 때만 키보드 포커스를 준다.

대화창 상단의 빈 곳과 작은 스택은 드래그로 옮긴다. 스택을 끄는 동작은 대화를 열지 않는다. 대화 영역의 빈 곳에서도 스크롤할 수 있고 위쪽을 읽는 동안 새 답변으로 화면을 강제로 내리지 않는다. 마지막 대화를 `×`로 닫으면 패널은 숨겨지고 Mac 메뉴 막대의 말풍선 아이콘에서 대화나 작업 목록을 다시 연다. 숨긴 창은 새 입력 때문에 자동으로 나타나지 않는다. 숨김·최소화는 프로세스 종료가 아니므로 작성 중인 초안을 유지한다.

설정 아이콘에서 Claude 모델과 생각 수준을 작업별로 고를 수 있다. 설정 저장은 모델을 호출하지 않고 다음 검토부터 적용한다. `model --model <모델 ID> --effort <수준>`은 로컬 기본값, `--session <ID>`는 그 작업의 설정이다. 실제 응답 모델은 Claude가 반환한 메타데이터만 표시하며 이전 기록에 없는 모델은 추정하지 않는다. GPT 모델은 현재 Work 설정을 따른다. AGY는 계속 꺼진다. Claude는 세션 저장을 끄므로 Claude 앱/CLI 대화 목록에 새 대화가 남지 않고, 로컬 실행기가 실제 검토 기록을 관리해 다음 호출에 전달한다.

## Work가 활성 상태일 때

- 단계 사이 `inputs pending <세션> --owner-thread <현재 Work ID>`로 새 입력을 읽는다. 승인 대기 중에는 `inputs wait <세션> --owner-thread <ID> --timeout 55`로 최대 55초씩 기다릴 수 있다. 기다림을 외부 호출과 함께 실행하거나 현재 사람의 답을 모델 출력으로 대체하지 않는다.
- 일반 메시지는 지시·질문이며 승인 결정이 아니다. 로컬에만 보관하고 개인 메시지를 Claude에게 자동 전달하지 않는다. 사람이 범위를 바꾸면 영향과 필요한 체크포인트를 먼저 준비한다.
- 명시적인 승인/보류 버튼의 `decision`과 화면에 제시된 정확한 `checkpoint_id`를 현재 미해결 질문·세션·변경할 수 없는 소유 Work와 대조한다. 실제 사람이 입력한 답만 처리한다. Work나 테스트가 만든 레코드는 사람의 승인으로 사용하지 않는다. 질문이 바뀌었으면 다시 보여주고, 이미 처리한 결정은 실행하지 않는다.
- 실제 사람의 결정을 확인한 현재 Work가 `work decide`를 실행한다. 입력 수집 자체는 결정을 바꾸거나 모델을 실행하지 않는다. 실행기가 사람 신원을 별도로 인증한다고 주장하지 않는다.
- 실제 답을 `work/`의 600 권한 파일에 저장하고 `inputs ack <입력 ID> --owner-thread <ID> --response <답변 파일>`로 표시한다. `Work 수신 대기`가 `도로 확인`으로 바뀌고 실제 GPT 답변이 같은 대화에 나온다. 읽기와 답변은 외부 모델 호출이 아니다.

## Work가 쉬고 있을 때

네이티브 UI는 정확한 세션에 입력을 저장하지만 지원되는 앱 메시지 도구를 독립 호출할 수 없다. 따라서 **저장 성공과 Work 도착은 구별한다.** Work가 쉬는 중이면 `Work 수신 대기`로 남는다. 공식 펫에 해당 협업의 “입력 확인”을 요청하면, 그 현재 사람의 요청을 받은 Work가 등록된 소유 Work에 지원되는 메시지 도구로 깨우는 경로를 사용할 수 있다. 도구가 없거나 도착이 확인되지 않으면 성공으로 보고하지 않는다. 자동 Work 깨우기·실시간 독립 응답을 보장하지 않는다.

## 로컬 입력의 경계

UI 인스턴스 토큰은 한 세션과 만료 시각에 묶고 해시만 저장한다. 클라이언트 UUID가 같은 재전송은 한 건이며 내용이 다르면 거부한다. 화면에 보인 질문이 바뀌면 새 승인을 거부한다. 토큰은 같은 로컬 UI 인스턴스의 경로 확인이며 독립적인 사람 신원 인증 수단이 아니다. 앱 자체의 도구 권한 요청은 이 버튼으로 대신 승인하지 않는다.

`chat --json`/`--text`는 모델 호출 없는 로컬 읽기다. `--post`는 UI의 제한된 stdin 전송 경계이며 사용자 메시지·정확한 질문·클라이언트 ID·별도 decision만 받는다. 키·다른 대화·저장소를 자동 수집하지 않는다.
