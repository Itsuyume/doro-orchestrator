# 도로협업에서 진행과 입력 처리

대화 목록은 한 번에 최대 3개 작업 높이로 표시하고 나머지는 세로 스크롤로 찾는다. 지난 대화·선택·삭제 취소 컨트롤은 스크롤 밖에서 유지한다. 협업창·말풍선·입력·설정·승인창은 macOS 라이트/다크 모드를 자동으로 따른다.

진행 중·승인 대기·입력 전달 중인 작업을 완료된 작업보다 먼저 표시하고 두 그룹의 경계에 구분선을 넣는다. 지난 대화가 펼쳐진 상태는 ↑, 접힌 상태는 ↓로 표시한다.

`bridge.py chat <session_id> --display panel`은 공식 펫을 그대로 두는 macOS 대화창이다. 펫 선택과 원본 이미지는 변경하지 않는다. 메뉴 막대 말풍선을 누르면 그 아래에 작업 목록을 연다. 상단 대화 버튼으로 목록에 돌아간다. 한 번에 한 대화만 표시한다. GPT·Claude는 왼쪽, 사람만 오른쪽이다.

위쪽 ↑는 대화를 dock 하나로 접는다. dock의 ↓는 다시 펼치고 ↑는 메뉴 막대로 숨긴다. dock·목록은 내용 크기로 고정하고 전체 대화만 크기 조절을 허용한다. 다른 앱·바탕화면을 누르면 펼친 대화와 접힌 dock 모두 메뉴 막대로 숨기며 초안과 읽던 위치·협업은 유지한다. 설정·승인창 이동은 자동 접기의 대상이 아니다. 창은 가장자리·여백·본문에서 드래그 가능하다. 입력칸은 글 선택·입력, 스크롤바는 스크롤을 우선한다. 말풍선은 우클릭으로 복사한다. 메뉴 막대 아이콘을 다시 누르면 창만 숨기고 메뉴 아이콘을 유지한다. 메뉴 막대의 종료 메뉴나 Command+Q는 UI 앱과 메뉴 아이콘을 종료한다. 창 수명 정책이 켜진 설치에서는 진행 중 외부 모델 호출도 중단하고 새 호출을 막는다. 다시 열어도 중단된 호출은 자동 재시도하지 않는다. 목록 행 ×는 해당 항목만 닫는다. 원래 Work·기록·질문은 유지된다. Spotlight에서 도로협업을 찾아 다시 실행하며 실행 중에는 ⌃⌥Enter로 연다. 다시 열면 메뉴 막대 아래로 돌아온다.

입력 초안·읽은 위치·펼친 발언은 작업별로 보관하며 재실행 뒤에도 복원한다. 로컬 `.doro/native/context-state.json`은 600 권한이고 UI 토큰·계정 정보는 저장하지 않는다. 개인 초안·입력은 Claude에 자동 전달하지 않는다. 전송 중 작업을 바꿔도 처음 선택한 목적지에만 도착한다. 등록된 협업의 이름·상태·대기 수만 표시하고 다른 Work를 자동 검색하지 않는다. Claude·AGY의 초록/회색 점은 enabled 설정이며 실제 인증이나 구독 잔여량이 아니다. 작업 전환과 모델 선택 자체는 모델 호출이 아니다.

Enter는 보내기, Shift+Enter는 줄바꿈이다. 별도 보내기 버튼은 두지 않는다. 작업명과 전송 상태는 한 줄 상단바의 남는 영역에서 흘러가며, 포인터를 올리거나 동작 줄이기가 켜져 있으면 멈춘다. 전체 문장은 도움말과 접근성 라벨로 읽을 수 있다. 입력 오류는 입력칸 가까이에 남긴다. 한글 조합 중에는 Enter로 글자만 확정한다. 실행기의 입력 한도를 넘거나 저장에 실패하면 내용을 보존하고 보내지 않는다. 불확실한 전송 ID는 종료 뒤에도 남겨 동일 입력의 중복을 막고, 자동 재전송하지 않는다. 저장 파일이 손상되면 원본을 유지하며 오류를 표시한다. 사용자가 ‘원본 보관 후 복구’를 누르면 기존 파일을 같은 폴더의 `context-state.backup-<UUID>.json`으로 보관한 뒤 현재 입력을 저장한다. 복구만으로 전송하지 않는다. 저장할 수 없는 새 초안·미확인 전송이 있으면 종료를 멈춘다.

## 승인창과 모델 선택

승인은 일반 말풍선이나 입력칸에 긴 설명을 붙이지 않고 별도 작은 창에 표시한다. 체크포인트 생성 시 `--brief <280자 이내 파일>`로 대상·범위·영향을 직접 작성하고 `--summary`에는 원문과 검증 근거를 보존한다. 요약을 임의로 자르거나 자동 생성하지 않는다. 요약 없는 이전 질문은 상세를 기본으로 펼친다.

질문은 같은 ID당 한 번만 자동 표시한다. 최소화 중에는 메뉴 아이콘에 승인 수를 표시하고, ‘승인’ 목록에서 정확한 작업을 골라 다시 연다. 나중에·닫기·Escape는 결정을 기록하지 않는다. 보류는 실행기의 `reject`이며 현재 변경을 적용하지 않고 사용자 방향을 기다리는 뜻이다. 승인/보류 답변을 큐에 넣은 뒤 실제로 접수된 선택과 Work 확인 대기를 표시한다. 같은 질문에 두 번째 결정을 넣지 않으며, 일반 채팅은 별도로 쓸 수 있다. 다른 작업으로 바꾸면 기존 승인창을 닫는다.

승인/보류가 로컬 큐에 저장되면 해당 질문 창은 즉시 닫고, 질문 수에서도 제외한다. 실제 답변과 Work 확인 상태는 대화에 남는다. 저장 실패 시에는 창과 오류를 유지한다. 접수와 실제 파일 적용을 같은 완료로 표시하지 않는다. 이미 답한 질문은 재팝업하지 않는다. 사용자가 승인 목록에서 직접 질문을 열었을 때만 키보드 포커스를 준다.

대화 영역의 빈 곳에서도 스크롤할 수 있고 위쪽을 읽는 동안 새 답변으로 화면을 강제로 내리지 않는다. 숨긴 창은 새 입력 때문에 자동으로 나타나지 않는다. 숨김·최소화 중에는 3초 간격으로 로컬 변경을 확인하고 실제 변경 시 작업 메타데이터만 읽어 승인 수를 갱신한다. 변경이 없을 때는 30초 안전 조회만 한다. 대화 본문·모델 호출·자동 팝업은 없다. 종료 시 전송 중인 입력이 있으면 먼저 전달을 확인한다.

대화 버튼 옆 Claude·AGY 설정의 탭에서 모델과 생각 수준을 작업별로 고를 수 있다. AGY의 사용 여부도 여기서 저장한다. 준비가 확인되지 않으면 AGY 점은 회색이며 이유는 설정창에 표시한다. 설정 저장은 모델을 호출하지 않고 다음 검토부터 적용한다. 성공하면 설정창이 닫히며 실패하면 입력과 오류를 보존한다. `model --model <모델 ID> --effort <수준>`은 로컬 기본값, `--session <ID>`는 그 작업의 설정이다. 실제 응답 모델은 Claude가 반환한 메타데이터만 표시하며 이전 기록에 없는 모델은 추정하지 않는다. GPT 모델은 현재 Work 설정을 따른다. AGY는 기본적으로 꺼져 있고 명시적인 사용자 요청으로만 활성화한다. `model --show`는 로컬 설정만 읽으며 모델을 호출하지 않는다. 켜져 있어도 이전 Claude 전용 입력을 AGY에 보내지 않는다. 새 공개 범위가 AGY를 허용해야 한다. AGY의 최근 CLI 모델은 초기화에서 확인한 핀값이며 서버 반환 모델과 구분한다. Claude는 세션 저장을 끄므로 Claude 앱/CLI 대화 목록에 새 대화가 남지 않고, 로컬 실행기가 실제 검토 기록을 관리해 다음 호출에 전달한다.

## Work가 활성 상태일 때

- 단계 사이 `inputs pending <세션> --owner-thread <현재 Work ID>`로 새 입력을 읽는다. 승인 대기 중에는 `inputs wait <세션> --owner-thread <ID> --timeout 55`로 최대 55초씩 기다릴 수 있다. 기다림을 외부 호출과 함께 실행하거나 현재 사람의 답을 모델 출력으로 대체하지 않는다.
- 일반 메시지는 지시·질문이며 승인 결정이 아니다. 로컬에만 보관하고 개인 메시지를 Claude에게 자동 전달하지 않는다. 사람이 범위를 바꾸면 영향과 필요한 체크포인트를 먼저 준비한다.
- 명시적인 승인/보류 버튼의 `decision`과 화면에 제시된 정확한 `checkpoint_id`를 현재 미해결 질문·세션·변경할 수 없는 소유 Work와 대조한다. 실제 사람이 입력한 답만 처리한다. Work나 테스트가 만든 레코드는 사람의 승인으로 사용하지 않는다. 질문이 바뀌었으면 다시 보여주고, 이미 처리한 결정은 실행하지 않는다.
- 실제 사람의 결정을 확인한 현재 Work가 `work decide`를 실행한다. 입력 수집 자체는 결정을 바꾸거나 모델을 실행하지 않는다. 실행기가 사람 신원을 별도로 인증한다고 주장하지 않는다.
- 실제 답을 `work/`의 600 권한 파일에 저장하고 `inputs ack <입력 ID> --owner-thread <ID> --response <답변 파일>`로 표시한다. `inputs get` 또는 `pending`/`wait`로 소유자가 원문을 처음 조회하면 `도로 확인`을 기록한다. 최종 `ack`는 별도의 답변 시각과 실제 GPT 답변을 같은 대화에 남긴다. 읽기와 답변은 외부 모델 호출이 아니다.

공식 `PostToolUse` 입력 알림이 설치되고 정상 신뢰된 환경에서는 다음 도구 실행 뒤에도 같은 `DORO_INPUT` ID 표식을 받을 수 있다. 원래 주 작업의 실제 thread ID와 소유자가 일치할 때만 원문을 읽고, 다른 에이전트는 처리하지 않는다. 알림 자체는 승인이나 원문 수신이 아니다. 이미 수신했지만 답변 중인 입력은 기존 작업을 이어가며 새 작업으로 중복 실행하지 않는다. 이미 read인 입력의 늦은 queue 표식은 재실행하지 않는다. 후크 비활성·출력 상한·도구 실행 중에는 기존 queue가 남으며 즉시 전달을 보장하지 않는다.

## Work가 쉬고 있을 때

네이티브 UI는 토큰을 검증한 `chat --post --wake`로 입력과 전달 대기를 함께 저장한 뒤 공식 `codex queue --thread <소유 UUID> --message <ID 표식>`을 호출한다. 인자에는 입력 원문·토큰·개인 경로를 넣지 않는다. 별도 Codex 메인 작업이나 재시도 데몬을 실행하지 않는다. 기존 Work가 다음 턴에서 표식을 수신하고 스킬의 DORO_INPUT 절차로 원문을 읽는다. 새 협업 시작 요청도 선택한 원래 Work에서 범위를 준비한다. 등록되지 않은 프로젝트를 추측하지 않는다.

화면의 ‘저장됨’, ‘Work 확인 대기’, ‘도로 확인’, ‘연결 실패’, ‘전달 확인 필요’를 구분한다. 큐 접수만으로 실제 Work 재개나 파일 반영을 성공이라 하지 않는다. Work가 실제 입력을 읽고 응답해야 수신 검증이다. Codex 앱이 실행 중이어야 하며 앱·버전에 따라 큐 소비가 확인되지 않으면 그 한계를 알린다.

같은 input_id의 중복 송신은 막는다. 확정 실패만 사람이 ‘다시 보내기’로 재시도할 수 있다. 타임아웃·중간 종료처럼 전송 여부가 불확실하면 자동 재전송하지 않는다. 입력은 저장된 채 남고 별도 Work를 대신 실행하지 않는다. Work 재개는 현재 Work 모델의 사용량을 쓰며 Claude를 자동으로 추가 호출하지 않는다.

## 로컬 입력의 경계

UI 인스턴스 토큰은 한 세션과 만료 시각에 묶고 해시만 저장한다. 클라이언트 UUID가 같은 재전송은 한 건이며 내용이 다르면 거부한다. 화면에 보인 질문이 바뀌면 새 승인을 거부한다. 토큰은 같은 로컬 UI 인스턴스의 경로 확인이며 독립적인 사람 신원 인증 수단이 아니다. 앱 자체의 도구 권한 요청은 이 버튼으로 대신 승인하지 않는다.

`chat --json`/`--text`는 모델 호출 없는 로컬 읽기다. `--post`는 제한된 stdin 저장 경계이고 `--wake`가 있어야 원래 Work에 전달하며 사용자 메시지·정확한 질문·클라이언트 ID·별도 decision만 받는다. 키·다른 대화·저장소를 자동 수집하지 않는다.

새 작업은 상단 ＋에서 내용을 입력하고 시작한다. 별도 GPT 대화 생성·원래 GPT의 중계·초안 보존은 [새 작업 연결](new-tasks.md)을 따른다. 창 여는 전역 단축키는 Control+Option+Enter이며 입력칸의 Enter 전송·Shift+Enter 줄바꿈과 구분한다.
