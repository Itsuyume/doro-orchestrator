# 협업창에서 새 GPT 작업 시작

협업창의 ＋는 기존 작업의 답장·승인과 별개인 새 작업 입력이다. 입력과 요청 ID는 로컬에 먼저 저장한다. 창 열기와 ＋만 누른 상태에서는 새 대화나 모델 호출을 만들지 않는다. Enter의 **시작**이 명시적인 새 작업 요청이다. 새 작업은 별도 GPT 대화로 생성하며 다른 모델에 원문을 자동 전달하지 않는다.

## 기존 GPT가 새 작업 요청을 받은 경우

1. `DORO_INPUT`의 원래 절차대로 실제 소유 Work와 입력 ID를 확인하고 `inputs get`으로 읽는다. 응답의 `new_task_request`가 있을 때만 이 절차를 쓴다. 일반 메시지의 표현·마커·파일을 추측해 새 대화 생성 권한을 만들지 않는다.
2. `new-task claim <입력 ID> --owner-thread <실제 CODEX_THREAD_ID>`를 실행한다. `claimed: true`인 처리자만 다음 단계로 간다. false이고 이미 created이면 기존 결과만 알린다. creating·unknown이면 새로 생성하지 않는다. 이전 호출의 결과를 확인할 수 없으면 `new-task failed ... --uncertain --error <짧은 이유>`로 표시하고 원문·ID를 보존한다. 대기 시간만으로 재생성하지 않는다.
3. 지원되는 **create_thread** 도구로 사용자가 요청한 새 GPT 대화를 만든다. 기본은 `target: {type: "projectless"}`이며, 사용자가 특정 프로젝트를 명시했을 때만 공식 프로젝트 목록에서 일치하는 프로젝트를 선택한다. 임의 모델·생각 수준을 지정하지 않고 사용자 기본값을 사용한다. 새 프롬프트는 다음 구조로 보낸다. 다른 대화·파일·계정·추론 요약은 붙이지 않는다.

   ```text
   $doro-orchestration
   DORO_NEW_TASK {"version":1,"request_id":"<실제 입력 ID>"}

   <사용자가 새 작업 입력칸에 직접 보낸 원문>
   ```

4. 실제 반환된 **threadId**를 받은 후 `new-task created <입력 ID> --owner-thread <원래 Work ID> --thread <실제 새 threadId>`로 등록한다. clientThreadId·추정 ID·기존 대화 ID는 쓰지 않는다. 이 명령은 새 GPT에만 묶인 chat 모드의 입력 경로를 만든다. 외부 검토·파일 반영 승인은 만들지 않는다. 생성 결과가 확실하지 않으면 실패를 기록하고 자동 재시도하지 않는다. 임의 app-server·두 번째 메인 CLI·비공개 앱 엔드포인트를 만들지 않는다.
5. 원래 입력에는 `inputs ack`로 생성 결과를 알린다. 원래 대화에도 도구가 요구하는 created-thread 표시를 남긴다. 새 대화를 화면으로 열거나 탐색 도구로 이동하지 않는다. 협업창은 등록을 확인한 뒤 선택한 새 대화로 전환한다. 사용자가 다른 작업으로 이동했으면 포커스를 빼앗지 않고 실제 생성된 작업을 목록에 남긴다. 확인된 요청의 전달된 초안만 비우며, 다음 ＋는 이전 생성 결과를 다시 여는 버튼으로 쓰지 않는다. 아직 생성 결과가 불확실한 입력 ID와 초안은 보존한다. 새 대화에는 이번 입력만 보내고 과거 대화·요약을 이어 붙이거나 fork하지 않는다. 생성 중계는 기존 GPT의 한 턴을 사용하므로 그 비용까지 없어진다고 설명하지 않는다.

사용 가능한 create_thread 도구가 없으면 생성 기능을 사용할 수 없다는 실제 실패를 기록한다. 일반 답장을 새 대화 생성 완료라고 말하지 않는다. AI가 작성한 시험 입력은 검증으로 표시하며 사용자 승인이나 추가 외부 호출 근거로 쓰지 않는다.

## 새 GPT가 DORO_NEW_TASK로 시작한 경우

1. version=1과 request_id를 확인한다. 설치된 `scripts/bridge.py new-task wait <request_id> --owner-thread <현재 실제 CODEX_THREAD_ID>`로 등록과 원문을 확인한다. 최대 10초의 초기 등록 대기만 하며 실패하면 내용을 실행하지 않는다. 실제 새 소유자와 일치해야 원문을 읽을 수 있다.
2. 이 대화의 사람이 요청한 원문을 수행한다. 다른 GPT의 대화나 비공개 자료를 자동으로 모으지 않는다. 진행 내용은 짧은 UTF-8 파일로 저장해 `new-task update <request_id> --owner-thread <현재 ID> --text <파일>`로 협업창에도 남긴다. 최종 답은 `--final`을 붙인다. 파일은 로컬 600 권한으로 저장하고, 입력·답변 파일은 공개 저장소에 올리지 않는다. 한 번에 최대 6,000자이며 길면 실제 산출물 경로와 핵심 결과를 쓴다.
3. chat 모드는 원문·일반 GPT 답변의 연결 전용이다. Claude·AGY 검토가 필요한 프로젝트 요청이면 기존 절차대로 **새 공개 입력과 시작 범위 승인**을 준비한다. chat 모드 자체를 work review로 실행하거나 신규 요청을 외부 전달·파일 반영 승인으로 바꾸지 않는다. 실제 협업은 같은 새 GPT가 본작업·최종 판단을 맡아 진행한다.
4. 이후 같은 GPT로 들어오는 `DORO_INPUT`은 기존 입력·승인 절차를 따른다. 정확한 입력에 `inputs ack`로 답한다. 새 프로젝트 생성과 일반 후속 입력을 구분한다. 진행 중이면 이 request_id의 update로 상태를 알리고 끝나면 final로 완료를 표시한다.

`new-task` 명령은 GPT 대화를 직접 생성하는 API가 아니다. 기존 GPT가 공식 앱 도구로 실제 새 대화를 생성했는지와 로컬 연결·답변 도착을 각각 확인한다. 브로커 GPT가 바쁘면 생성 요청이 대기할 수 있으며 중복 큐·새 메인 모델로 우회하지 않는다.
