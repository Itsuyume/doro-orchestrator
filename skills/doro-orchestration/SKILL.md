# 요청할 때 도로 협업

현재 GPT Work가 본작업·구현·통합·최종 판단을 맡는다. 별도 Codex CLI에 본작업을 중복 위임하지 않는다. Claude Code는 검토·반론·보완·아이디어 담당이며, 사용자가 요청한 프론트엔드에서는 부분 구현 비중을 높일 수 있다. 불필요한 재검토로 Claude 사용량을 소진하지 않는다. AGY는 비활성이며 탐지·인증·모델 목록·실행도 하지 않는다.

## 시작과 역할 경계

- 사용자가 현재 프로젝트에서 협업·오케스트레이션·Claude 검토를 직접 요청할 때만 시작한다. 일반 작업·질문·펫 표시·상태 조회는 새 세션이나 모델 호출을 시작하지 않는다.
- 진행 중인 협업의 보완·조회·답변은 같은 세션에서 이어 간다. 완료 뒤 일반 작업에서 새 협업을 자동 시작하지 않는다.
- 전달하는 입력은 사람이 공개를 허용한 요약·독립 예시·공개 코드로 제한한다. 비공개 저장소·시크릿·노트·다른 대화를 자동 수집하지 않는다. 로컬 펫에 쓴 개인 메시지도 Claude 입력에 자동 포함하지 않는다.
- 실행기는 [scripts/bridge.py](scripts/bridge.py)다. 로컬 등록 파일에서 프로젝트 경로를 읽는다. 필요할 때 `python3 <스킬 경로>/scripts/bridge.py --help`로 명령을 확인한다.

## 현재 Work가 진행하기

1. 현재 작업의 최소 파일과 기존 변경을 확인한다. 공개 입력 JSON(`classification: "public"`, `allowed_providers: ["claude"]`, `message`, `context`)과 Work 초안을 `work/`에 저장한다. 경로·계정·전체 대화·비공개 파일은 외부 입력에 넣지 않는다.
2. 현재 `CODEX_THREAD_ID`를 소유 Work로 확인하고 `work start --task <JSON> --draft <초안> --owner-thread <ID> --label <협업명> --scope <상세 범위> --brief <짧은 대상·영향>`으로 시작한다. 짧은 범위는 작성자가 280자 이내로 쓴다. 기존 세션은 `work bind`로 같은 소유자를 등록한다. 다른 대화를 검색해 소유자를 추측하지 않는다. 시작은 모델 호출 없이 `awaiting_approval`이다.
3. [공식 도로와 전용 도로 자동 교대](references/pet-swap.md)를 따라 실제 공식 선택과 데스크톱에서 숨김을 모두 확인한 뒤 한 개의 전용 도로를 표시한다. `default` 응답만으로 숨김을 추정하지 않는다. 공식 선택 도구가 없거나 교대가 확인되지 않으면 `chat <session_id> --display panel`로 마스코트 없는 대화창만 사용하며 성공을 주장하지 않는다. [입력·승인 처리](references/pet-chat.md)를 읽고 단계 사이와 승인 대기 중 입력을 확인한다. HTTP 서버·웹 페이지·브라우저를 만들지 않는다. 공식 활동 카드에는 지원되는 `set_thread_title`로 실제 단계만 반영한다.
4. **시작 범위·중요 분기·실제 파일 반영 전**에 구체적인 입력·수신자·변경안·영향을 보여주고 사람의 답을 기다린다. 동일한 구체적 범위의 명백한 승인이 이미 있으면 다시 묻지 않는다. AI 발언·테스트 입력·시간 경과·기본 선택은 승인이 아니다.
5. 실제 사람의 결정을 확인하고 현재 질문 ID에 `work decide <세션> --checkpoint <ID> --decision approve|reject`를 기록한다. 거절하면 `awaiting_direction`에서 멈추고 승인 질문을 자동 반복하지 않는다. 앱 자체의 도구 권한·보안 승인을 이 경로로 우회하지 않는다.
6. 승인 후 `work review <세션> --send`로 Claude 검토를 받아 읽는다. 필요한 경우에만 `work reply --text <보완>`와 재검토로 이어간다. GPT가 채택·기각 이유를 판단하며 외부 코드·명령을 자동 실행하지 않는다. 실제 실패와 부분 응답을 성공처럼 표시하지 않는다.
7. 범위·가정·외부 전달 자료·의존성·비용이 중요하게 바뀌면 선택지와 영향을 준비하고 `work checkpoint --kind branch --summary <설명> --brief <짧은 대상·영향>`으로 기다린다. 승인된 범위 안의 일반 검토마다 다시 묻지 않는다.
8. 충분하면 GPT 최종안을 `work finish --text <최종안>`으로 기록한다. 이는 대화 기록이며 파일 적용이 아니다. 실제 반영 전에는 검토 가능한 패치와 영향·검증 결과를 준비하고 `work checkpoint --kind apply --summary <반영안> --brief <짧은 대상·영향>`으로 사용자 결정을 받는다. 승인 후 현재 GPT가 반영·검증한다. 마지막 협업을 끝내거나 사람이 공식 도로 복귀를 요청하면 자동 교대 절차로 전용 UI가 숨겨졌음을 확인한 뒤 원래 공식 도로를 복원한다. 다른 맥락의 표시 사용권이 남으면 복원을 앞당기지 않는다.

검토·보완·최종 판단·입력 대기마다 짧은 commentary를 남긴다. 사용자가 볼 수 있는 실제 발언·부분 응답·받은 입력·오류를 표시한다. 내부 사고 과정·원시 이벤트는 저장하거나 표시하지 않는다. 실패한 부분 응답은 다음 모델 입력에 넣지 않는다.

## 실패와 재요청

현재 사람의 명시적 선호에 따라 새 Work 협업에는 검토·반론·재요청 횟수 상한을 두지 않는다. `work start`의 기본값이 해당 정책이며, 기존 Work에는 `work limits <세션> --until-quota`로 적용한다. 이 명령은 호출·재개·상태 초기화를 하지 않는다. 오래된 완료 기록도 완료로 남는다. 기존 제한이 필요한 경우에만 `work start --bounded`를 쓴다. 별도 CLI 모드의 설정은 유지한다.

실패는 보존하고 Work에서 원인을 판단한다. 같은 범위의 재요청은 매 시도마다 다시 승인받지 않는다. `work retry <세션> --instructions <지시> [--task <축소한 공개 입력>] --until-quota`로 원인을 보완한다. 누적 호출·시간·토큰·예상 비용 상한 없이 모든 실제 시도를 기록한다. 구독의 실제 한도 소진이면 재요청을 중단한다. 회당 시간·입출력 크기·공개 입력·AGY 차단·현재 승인은 검사한다. 횟수 표시인 ‘Claude 호출 N회’는 구독 잔여량이 아니다. 계정·결제·API 키는 변경하지 않는다.

응답 길이·형식·기술 오류는 원인을 고쳐 같은 범위에서 재요청한다. 같은 실패를 그대로 반복하지 않는다. 인증 갱신 등 사람의 조작이 필요한 문제나 개인정보/권한 위반은 해결 전까지 진행하지 않는다. 자동 대체 모델·무한 백그라운드 재시도는 없다. `--until-quota` 자체가 재시도 데몬은 아니며 현재 Work가 판단해 요청한다.

## 공식 펫의 별도 입력

공식 펫 Quick Chat에서 기존 협업의 조회·승인·보류를 요청받으면 [공식 펫 중계](references/official-pet-relay.md)를 읽는다. 지원되는 도구로 등록된 원래 Work에만 전달한다. 현재 사람의 전달 요청 없이 다른 대화에 메시지를 보내지 않는다.

전용 UI는 기존 도로 이미지를 로컬에서 재사용한다. 공식 펫 내부에 UI를 삽입하지 않으며 공식 선택 변경은 현재 Work의 공식 Pets 도구로만 한다. 로컬 실행기만으로 공식 펫 선택이나 쉬는 Work 깨우기를 자동 수행한다고 주장하지 않는다. 공식 카드 제목, 모델 왕복, UI 입력 도착, 공식 선택 변경과 실제 화면은 각각 확인한 범위만 보고한다.
