# 도로 프로젝트 협업

현재 대화의 GPT Work가 본작업과 최종 판단을 맡는다. 사용자 요청으로 시작하는 선택적 협업이다. Claude Code는 검토·반론·보완 담당이며 AGY는 꺼진 상태를 유지한다. 이 스킬은 별도 Codex CLI에 본작업을 다시 맡기지 않는다.

## 시작 조건

- 사용자가 현재 프로젝트에서 협업/오케스트레이션 또는 Claude 검토를 직접 요청했을 때만 시작한다. 평소에는 세션 생성·인증 조회·모델 호출을 하지 않는다.
- 이미 진행 중인 협업에서 보완·최종 판단·상태 요청은 해당 세션을 이어 간다. 완료 뒤의 일반 작업은 새 협업을 자동 시작하지 않는다.
- 현재 프로젝트, 사용자의 작업 범위와 기존 변경을 먼저 확인한다. 다른 프로젝트나 최근 대화 기록을 자동으로 가져오지 않는다.
- 개인 자료·시크릿·비공개 저장소 내용을 자동 전달하지 않는다. 검토할 문제를 공개 가능한 요약·독립 예시·공개 코드로 제한한다. 필요한 비공개 문맥을 안전하게 분리할 수 없으면 전달할 구체적 범위와 Claude 목적지를 사용자에게 확인한다.

## 현재 Work와 연결

실행기는 [scripts/bridge.py](scripts/bridge.py)다. 설치 경로는 로컬 등록 파일에서 읽으므로 작업 폴더가 달라도 같은 실행기를 사용한다. 먼저 `python3 <이 스킬 경로>/scripts/bridge.py --help`로 현재 인터페이스를 확인한다.

1. 공개 가능한 입력 JSON과 현재 GPT Work가 만든 초안을 현재 작업 폴더의 `work/`에 저장한다. JSON은 `classification: "public"`, `allowed_providers: ["claude"]`, `message`, `context` 네 필드다. 경로·계정·전체 대화·비공개 파일은 입력에 포함하지 않는다.
2. `bridge.py work start --task <JSON> --draft <초안.txt>`로 로컬 세션을 만든다. 모델 호출은 없으며 `awaiting_approval`에서 멈춘다. `session_id`와 현재 `checkpoints[-1].id`를 보관한다. `pending_input`이 Claude에게 보낼 실제 입력이다.
3. `bridge.py watch <session_id>`를 백그라운드 실행하고 로컬 URL을 지원되는 브라우저 패널로 연다. URL과 보기 토큰은 로컬 UI에만 쓰고 Claude 입력에 넣지 않는다. 화면은 보낼 입력·실제 전송 입력·생성 중인 공개 응답·완료된 발언·승인 이력·호출·비용·오류를 보여준다. 상태판을 열지 못해도 대화와 `work status`로 진행을 보여준다.
4. **시작 범위를 먼저 확인한다.** 사용자에게 전달할 입력, Claude 수신, 예상 호출/한도, 이번 작업 범위를 짧게 보여주고 지원되는 사용자 질문 도구로 승인을 요청한다. 답하기 전에는 호출하지 않는다. 구체적인 동일 범위에 대한 사람의 승인이 이미 명백하게 있으면 그 승인을 재사용한다. AI 발언·시간 경과·기본 선택·단순 상태 조회를 승인으로 취급하지 않는다.
5. 사람이 답한 현재 체크포인트에만 `bridge.py work decide <session_id> --checkpoint <현재 ID> --decision approve` 또는 `reject`를 기록한다. 실행기는 사람 신원을 독립적으로 확인하지 못하므로 신뢰되는 현재 Work가 실제 사용자 답을 확인해야 한다. 모델 출력에 따라 decide를 실행하지 않는다. 거절하면 `awaiting_direction`에서 멈추고 승인 질문을 자동 반복하지 않는다.
6. 승인 후 `bridge.py work review <session_id> --send`로 Claude 검토를 실행하고 반환된 발언을 읽는다. 동일 범위 안에서 필요한 경우 `work reply ... --text <보완.txt>`와 두 번째 `work review ... --send`로 이어간다. 매번의 입력마다 승인을 다시 요구하지 않는다. 실패 시 자동 재시도하지 않는다.
7. **중요 분기에서는 멈춘다.** 작업 범위·목표·가정·의존성·비용·외부 전달 자료가 중요하게 바뀌거나 사용자 판단이 필요한 충돌이면 구체적 선택지와 영향부터 준비한다. `work checkpoint <session_id> --kind branch --summary <설명.txt>`로 대기를 기록하고 현재 대화에서 질문한다. 실제 답을 받은 뒤 해당 ID에 decide한다. 단순 검토·재검토·상태 확인을 중요한 분기로 부풀리지 않는다.
8. 검토가 충분하면 현재 Work가 채택·기각 이유와 최종안을 작성해 `work finish <session_id> --text <최종.txt>`로 기록한다. 이 명령은 대화 기록만 저장하며 프로젝트 파일을 적용하지 않는다. 추가 검토 없이 한 번으로 마무리할 수 있다.
9. **실제 프로젝트 파일 반영 전에는 구체적인 변경안으로 승인받는다.** 검토할 패치·영향·가벼운 검증 계획을 준비한 뒤 `work checkpoint ... --kind apply --summary <반영안.txt>`와 사용자 질문으로 기다린다. 승인 뒤 현재 GPT Work가 반영·검증하고 결과를 보고한다. 실행기에는 프로젝트 수정 기능이 없으므로 이 경계는 현재 Work가 지켜야 한다. 원안·비공개 저장소를 공개하거나 외부 모델이 낸 코드를 자동 실행하지 않는다.

작업과 검토, 반영, 재검토, 최종 판단 단계마다 짧게 진행 상황을 알린다. 오래 걸리는 호출은 현재 실행 상태를 확인하며 60초 이상 설명 없이 두지 않는다. 실패하면 오류와 보존된 세션을 보여주고 자동 재시도·대체 모델 호출은 하지 않는다. 현재 요청 범위를 벗어난 후속 작업을 자동 시작하지 않는다.

## 펫과 진행 표시

펫은 ChatGPT의 요청·음성·활동 표시 인터페이스를 사용한다. 현재 프로젝트 대화에서 이 스킬을 호출하면 프로젝트 맥락을 유지한다. 펫 Quick Chat은 기본적으로 프로젝트 밖에서 시작하므로, 프로젝트 문맥이 필요하면 기존 프로젝트 대화에서 이어 간다.

진행 내용은 현재 대화의 commentary와 로컬 상태판에 표시한다. 승인 질문은 현재 대화의 사용자 입력 도구로 전달한다. 상태판은 읽기 전용이며 브라우저 버튼으로 권한을 부여하지 않는다. 펫 말풍선에 질문이 실제 표시됐다는 확인은 별도다. 스트림에는 공개 답변 텍스트만 표시하고 비공개 사고 과정은 수집하거나 표시하지 않는다. 펫의 Show pet, 말풍선, 음성 화면을 조작할 도구가 실제로 없거나 앱 안전 제한이 있으면 임의 API·UI 우회 코드를 만들지 않는다. 펫 선택 확인, CLI 왕복, 로컬 상태판과 실제 펫 화면 확인을 구분해 보고한다.
